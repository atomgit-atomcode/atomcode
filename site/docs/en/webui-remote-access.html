常见问题

Remote access

Run /webui and scan the relay QR code with your phone browser. No VPN or public listening port is needed.

Connect

  1. Keep AtomCode running and run /webui. It opens the local browser and prints a phone link and QR code.
  2. Scan with your phone browser, or copy the relay link from the WebUI Remote access dialog. The devices may use different networks.
  3. The phone and TUI share the same conversation. /webui stop, signing out in the terminal, or exiting AtomCode stops relay sharing.

Standalone: atomcode webui. Local only: /webui --local or atomcode webui --local. Explicit /webui lan or --host <address> uses the local network instead of automatically connecting a relay.

Connection failures

Local access remains available if relay setup fails. The terminal and Remote access dialog explain the failure. If WebUI is unsupported, upgrade the relay server and install the matching WebUI assets, then retry /webui. Use ATOMCODE_APP_RELAY to select an existing compatible relay and ATOMCODE_ENABLE_RELAY=0 to disable relay access.

Relay address

The default HTTPS relay is https://relay-atomcode.atomgit.com; no extra configuration is needed. On your phone, open the pairing link generated by AtomCode or scan its QR code.

Self-hosted relay requirements

The address override does not install a server. relay-client is not a relay server. The server is maintained in the separate atomcode-relay project; this guide provides neither server source nor a public download. Contact maintainers through a project Issue to confirm compatible server artifacts, supported platforms, and matching built WebUI assets. A public Docker image is not implied.

After obtaining a compatible server, place it behind HTTPS with WebSocket upgrades and unbuffered SSE forwarding. For containers, listen on the container network and expose the port only to the reverse proxy; another container cannot reach its loopback address. Set ATOM_RELAY_ADMIN_SECRET, limit ATOM_RELAY_MAX_TUNNELS (for example, 10 for personal use) and ATOM_RELAY_MAX_CONCURRENT, and enforce registration rate and connection limits at the reverse proxy. Serve compatible built assets using ATOM_RELAY_WEBUI_DIR, or use ATOM_RELAY_WEBUI_BUNDLES_DIR with the supplied versioned bundle installation instructions.

Before starting AtomCode, set ATOMCODE_APP_RELAY=https://relay.example.com and ATOMCODE_APP_RELAY_SECRET to match the server registration secret. Existing /app and /webui use the official relay-client; the server must implement its handshake and forwarding protocol. Check /health, registration, pairing, streaming, and reconnection separately. Registration secrets, route tokens, and WebUI access tokens are distinct credentials.

Until server artifacts are available to you, keep using an existing SSH reverse tunnel or VPN. Operators manage their own TLS, access, bandwidth, and upgrades. Self-hosting does not provide model inference credits.

Security and lifetime

The link grants access: keep it private. HTTPS protects transport; the local WebUI still checks its access token. The relay can process traffic; this is not end-to-end encryption. Pairing credentials survive reload in tab-scoped sessionStorage and are cleared when the tab closes. Network disconnects reconnect automatically. Access stops while the computer is asleep, offline, or AtomCode has exited.

Local network alternative

/webui lan remains available on the same Wi-Fi. /webui --host <virtual IP> also works with an existing VPN. These local HTTP connections require a trusted network.
