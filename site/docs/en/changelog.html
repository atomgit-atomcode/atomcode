v5.2.9 2026-11-26

Overview

This release is about teamwork, long-session stability and everyday controls. Team members can hand work over to each other under an explicit authorization instead of routing everything through the lead; members can opt into request budgets and task cost accounting. Sessions gain cross-project browsing and resume, previews and cleanup of old sessions, and a write guard — an existing file the session never touched is no longer overwritten. The review text from before a compaction can be expanded again.

The terminal and the web page were reworked together: /provider is now a list → detail pair, and the WebUI Git panel follows the VSCode source-control layout with read-only access to team members' conversations. On the security side, failed local API authentication is rate-limited and token comparison is constant-time. On the performance side, streamed replies are appended in place and rendered incrementally, session history and event logs are read incrementally, and file-index filtering no longer lowercases every entry.

Changes

  • Authorized handovers between team members: Members can hand tasks and conclusions directly to each other under an authorization instead of routing everything through the lead. tell_parent requires the delivered content to actually reach the report, a read-only member is told at once how to deliver, a member that stops after a progress report wakes the lead, and a member reporting completion reminds the lead to check it before stopping it. Members can opt into request budgets and task cost accounting, roles can look up read-only MCP tools by duty and verify the results, and delivery checks distinguish members with and without a shell.
  • Write guard for files: write_file no longer overwrites an existing file this session never touched. Loop detection counts per session, compaction and overflow guards compute the window from the current agent's model, repeated retries of malformed tool calls are bounded, long-thinking models lose fewer useless rounds and share one streaming timeout.
  • Browse and resume sessions across projects: The TUI can browse and resume sessions across working directories and preview and clean up old sessions. /agents lists one-shot task sub-agents, with the header carrying a sub-agent label. Background tasks read the session event log incrementally, history loading is faster and merges session preview requests, and the session start notice is de-duplicated while the SSE stream is consumed.
  • Review text from before a compaction: Recall can expand the review text from before a compaction; team member sessions can be compacted too, and a delegation kept after a member's compaction is marked as a historical message; compaction discloses the user requirements dropped in favor of an alternative.
  • /provider is now a list → detail pair: Enter / Ctrl+E / Ctrl+D behave the same throughout, forms use fixed key meanings and drop ^o / ^f and the Key field; the detail page offers "add and use" when no model is available, and the qualification is single and can be explicitly withdrawn.
  • WebUI source control follows VSCode: The Git panel follows the VSCode source-control layout, with the discard and commit scope, read-only rendering and empty-repository loading fixed; a session goal status bar with live timing was added, team members' conversations can be viewed read-only, the attachment menu is no longer cut off on small screens, and larger images can be pasted in live chat.
  • Local API authentication hardened and rate-limited: Failed local API requests are rate-limited by count, valid tokens stay usable during a block, token comparison is constant-time, Windows sets and verifies a user-only ACL for credential files, and panic telemetry is scrubbed while WebUI SSE events are size-limited.
  • Streamed replies append in place: The TUI no longer copies the whole reply for every delta — it appends in place and renders incrementally, and buffered deltas survive a view switch. Unchanged render rows are reused, but only after the amended text is checked; generation speed excludes burst frames so the number is no longer inflated.
  • file-index filtering is faster: Filtering no longer lowercases every entry and keeps only the top 30 — the selection is bounded and totally ordered, non-ASCII needles reuse one lowercase buffer, ASCII needles skip folding, and candidate clones and comparisons are bounded.
  • Terminal interaction fixes: The @ mention menu no longer pops up again after Esc, rejected tokens are identified by offset and text, the browse state keeps the rejection record, editing and cursor tracking are correct, a late receipt no longer closes the strength selector, Esc during a turn no longer discards the background-task completion notice, short screens no longer trade the command line for the panel's footer, narrow screens drop the timer before the badge state, the approval panel keeps a separating line between legend and status bar, and approvals on routes with no answer are hidden.
  • The /goal badge shows its running time: It counts up while running and freezes when paused, using only its own samples. The status bar shows the current member's worktree branch, and the footer reminder is rechecked immediately after a quota recovery.
  • Captured process output is bounded: Captured process output has a cap, truncated foreground output keeps its encoding, and the TUI live cache is capped as well.
  • AI inline completion (ghost text): The editor extension and the daemon side support AI inline completion, expired completion requests are cancelled and the originally inserted text is preserved.
  • VS Code chat focus recovery: Alt+Tab back restores the chat input focus and intercepts a lone Alt, with the focus-recovery condition tightened.
  • Session and runtime consistency: The running state is synchronized and history loading blocks less; repeated tool checks are fewer and tasks end in time; background reviews keep their single-execution limit, and the peak whole-document copy in long-session requests and subscription catch-up is reduced.
  • Site and docs rework: The bilingual changelog is shown with unified branding, the footer wordmark becomes a permanently lit "fluorescent horizon"; the site and the docs pages were visually reworked, and the mobile installation experience improved with the docs calibrated.

v5.2.8 2026-11-20

Overview

This release makes "moving over from another AI coding tool" a real workflow: the new atomcode import command and /import scan the instructions, skills, MCP servers and provider settings left behind by Claude Code, Codex and OpenCode, explain item by item what already takes effect, what can be brought over and what cannot, and write provider accounts only after confirmation. Structured Git status, configurable vision preprocessing models, hosted web search with automatic failover give both the model and the user a more reliable view of the current situation.

Stability work focuses on long thinking and streaming. Continuous reasoning has no cumulative time limit, and reasoning content refreshes the stream idle timer. SSE line buffers have a size limit and scan only new bytes. Sessions, compaction, background tasks, teams and sub-agents have fewer races and polling loops. The terminal now guides first-time model setup and sign-in recovery, and @ session references can be filtered to the current working directory.

Changes

  • Import another AI coding tool's assets: Add atomcode import (--json for a machine-readable report, --apply to write accounts after per-item confirmation, --yes to skip confirmation for accounts without a literal credential) and a TUI /import panel, scanning Claude Code, Codex and OpenCode instructions, skills, MCP servers and provider accounts. The report shares one skill-root resolution rule with the runtime, so it cannot claim a skill is in effect that the runtime does not read. Provider accounts already present in the configuration are reported as imported rather than offered again, and credentials are compared by kind only, never by value. Anything deliberately left out shows up in the exit code, so a script is never told everything went in when it did not.
  • Structured Git status: Add a git_status tool that returns the branch, HEAD, upstream, ahead/behind commit counts and the staged, unstaged, untracked and conflicted paths in one call. Paths are repository-relative and exclude uncommitted changes inside submodules. It is read-only, does not fetch, and reports unavailable comparisons as nulls rather than guesses. Add a configurable diff wrapping policy so long diff lines are no longer cut off on narrow terminals.
  • Vision preprocessing and search: Configure the vision preprocessing model (VL) from the TUI and WebUI, with multimodal requests following a separate provider and separate streaming path. Web search gains hosted backends and automatic failover, switching across services in routing order; a legacy Exa selection migrates to auto.
  • Providers and models: Add vendor protocol choices. Model discovery preserves errors from providers and shows models.dev suggestions only when the protocol or endpoint does not support listing models. Expand the Alibaba, Xiaomi, Kimi and Tencent presets and keep subscription credentials separate from plan URLs. Support a per-model output token budget, and let CodingPlan name a provider account per model with automatic gateway whitelisting. Switching models can warn that the next message may exceed the context window or that automatic compaction is about to start. An unknown window stays silent.
  • Code intelligence and prompts: The built-in LSP tool's diagnostics are no longer empty — on Windows the URI a server returns (lower-case drive letter and a percent-encoded colon) differs from the one sent in didOpen, so the whole push was dropped; the lookup now uses the filesystem's path identity. The system prompt asks for important conclusions to rest on inspected evidence, to distinguish observation from inference, and to report failed or unperformed checks honestly.
  • Long thinking and streaming: Continuous reasoning is no longer cut off by a cumulative time limit — while the model keeps producing reasoning content the request keeps waiting, the first-response and stream-idle deadlines still apply and reasoning content refreshes the idle timer, and the manual and automatic recovery paths after a reasoning timeout are removed. Auxiliary calls of a model with a configured reasoning effort (session title, compaction summary and similar) inherit the model's default effort, an explicit value wins, and the effective effort and its source are logged. Bound SSE lines in the Anthropic, Ollama and Responses decoders: a line or unterminated tail above 16 MiB ends the stream with a terminal error. The decoders scan only new bytes instead of re-draining the buffer per line. Bare scalar enums in tool schemas now carry a type, fixing HTTP 400 responses from strict validators such as Volcano's kimi-k3-1-pro.
  • Sessions, compaction and recovery: Report a rejected summary separately from "nothing to compact" and keep the diagnostics. Summarize long histories in recoverable windows. Name the reason for a refused session switch, report a turn that ended abnormally when resuming, and keep Unavailable/Stale typed across the embedded boundary. A rewind still takes effect when checkpoint retention fails, and rewind storage gains a retention bound so snapshots do not accumulate without limit.
  • Background tasks, teams and sub-agents: Align background waits with host wakeups, bound the cancellation wait, preserve pending requests and limit the cost of Git statistics. Team members stop polling for status and resolve qualified model routes. Sub-agents support read-only Grok and OpenCode delegation, with a preflight check that reports blockers explicitly.
  • WebUI and TUI experience: Session browsing keeps sessions held by other runtimes read-only and shows their activity. It offers independent forks, serializes history refreshes, and retries the final refresh. Workspace file previews link to the Git panel and bound the cost of read-only statistics. Model selection and reasoning effort share one control, with model labels and chronological turn navigation preserved. The turn highlight moves past completed reply tails. Mobile composer controls remain accessible by touch, and offline pages gain contrast in dark mode. Interrupted WebUI response streams finish cleanly. The workbench Git panel shows an empty state outside Git repositories. The TUI uses a blinking bar cursor and leaves room for it next to the empty-composer placeholder. It measures generation speed over streamed output, excludes display prompts from copied user messages, and wraps long diff lines by display policy.
  • TUI model setup and sign-in recovery: On first launch, sign in to CodingPlan or choose a provider from the welcome screen. Click the authorization link to open it or press c to copy it. After signing out or when sign-in expires, the TUI points to /login or /provider and preserves the draft during sign-in recovery. CodingPlan models can show localized aliases and descriptions. Search slash commands by description in the TUI and WebUI. In the TUI, /theme opens the theme setting, and changes apply after restart.
  • Find session references by working directory: In the TUI, use @ to find local sessions from other working directories, or narrow the list to the current directory with “Sessions · this workspace.” Search by session ID or preview text. Unnamed sessions can show their first saved user message even if the turn never finished. Invalid references report the specific format error.
  • Tool approvals: TUI tool approvals require explicit confirmation. Regular typing and input methods remain available for drafting. Managed headless runs can use --require-approval-hook to require a user-level approval hook covering every tool. A call is blocked if the hook fails, times out, or does not explicitly approve it.
  • Compaction and project knowledge: Compaction reuses the already-sent request prefix where possible and treats a tool call during summarization as an incomplete summary. Previews of compacted tool output keep the beginning and end so final errors and exit details remain visible. The project knowledge index can list when a topic applies, why it matters, and its file path. The model opens relevant notes and source evidence as needed.
  • Windows WebUI and version rollback: On Windows, the WebUI uses a system-assigned port if no port was specified and the default port range is unavailable. After a version rollback, startup honors the rollback and suppresses the previously staged automatic upgrade.
  • Import and batch operations: Import reports flag failed session scans and identify where MCP settings came from. Large reviews run in batches and report how much finished if they time out. If a batch search-and-replace write fails, the tool attempts to restore verified writes and reports the result.
  • IDE plugin improvements: The VS Code chat panel zooms its font with Ctrl (Cmd on macOS) plus the mouse wheel, and a change to atomcode.fontSize takes effect immediately without reloading the window. Body and code block sizes scale together.
  • Code review and tools: Reviews trace timing and share Git evidence, candidate verification is scoped to the changed file, and merged dimension tags are compared as a slice. The todowrite full-plan receipt becomes a status count, and background review presets a task title to avoid reporting tools as unavailable. AtomGit tool arguments parse leniently and write paths give a consistent UN_KNOW self-correction hint. The grep sensitive-path check no longer round-trips JSON per file and keeps single-quote boundaries.
  • Network and credentials: Use Termux DNS configuration when the system resolver is unavailable, fixing the static Linux build falling back to a loopback address when it cannot read /etc/resolv.conf, which blocked login. Keep relay diagnostics for remote task recovery. Manage saved SSH credentials from the TUI, diagnose unattended credential problems and suppress unattended prompts. Permission rules save literal Bash rules without wildcard expansion. Telemetry scrubs the longer path first and redacts provider errors before sending them.

v5.2.7 2026-11-12

Overview

This release improves long-running tasks and everyday controls: pause and resume all MCP servers for a session, load long conversation histories on demand, and recover more reliably from interruptions. It also expands skill invocation, debugging and project setup, with improvements to the WebUI workspace, terminal input and tool diagnostics.

Changes

  • Pause and resume all MCP servers: Use Ctrl+S at the top of the /mcp list to pause all MCP servers and press it again to resume. Controls are available in both TUI and WebUI, apply only to the current session, and preserve individual server configuration. Fix non-ASCII paths during environment variable expansion and improve MCP tool search relevance.
  • Long histories and context compaction: TUI and WebUI load display history in pages on demand. Bound summary inputs and old tool records, reduce copying and repeated computation, and distinguish a failed summary from a compaction that needs no changes.
  • Recovery and task progress: Improve recovery of accepted prompts after interruptions and keep todo records aligned across undo, rewind, forks and cancellation. Verify quota availability before resuming paused loops, with bounded retries and jitter for automatic recovery.
  • Automatic browser workflows: Configure a separately installed browser backend once through /browser, then describe webpage navigation, forms, clicks or screenshots to automatically load browser guidance and use connected tools. Existing approvals and explicit session reload remain; no per-task skill or slash command is required.
  • Skill names and invocation: Support Chinese skill names, separate display titles and multiple $skill references in one input. Add usage history and conservative spelling suggestions.
  • Debugging and project setup: Add DAP debugging and local adapter discovery. Project setup checks existing capabilities and offers optional tool installation with confirmation. An optional read-only architecture evidence capability can be enabled in shared settings.
  • Task checks and automatic review: Add configurable, audited checks for task handoffs and automatic review guidance. Improve background review permission inheritance, execution limits and failure reporting, including blocked writes by team members.
  • WebUI workspace and navigation: Pin, clear and remove workspaces, resize the sidebar, and view the current Git branch and session identity. Improve cross-client image retention, file refresh, narrow layouts and scroll positioning for newly submitted turns.
  • Terminal input and upgrade feedback: Show download progress, speed and remaining time during upgrades. Ctrl+C clears nonempty input first. Improve Windows and HarmonyOS scrolling, Unicode input and script encoding warnings, and clarify when the lead agent is waiting for members.
  • Tool results and diagnostics: Reject undefined replacement capture groups that could erase text. Report invalid todo IDs, invalid structural search patterns and ambiguous symbols explicitly. Patch import errors identify the failing stage and path; artifact storage can fall back to a temporary directory.
  • Model transport and efficiency: Improve streamed tool arguments, missing call IDs and SSE buffering. Reduce repeated context estimation and tool execution work, compress embedded WebUI assets, and expose native session identity in headless JSONL startup events.

v5.2.6 2026-11-05

Overview

This release focuses on continuity for long-running tasks and a more consistent experience across clients. Sessions can recover saved partial output and execution records after an abnormal exit, selected original task requirements survive context compaction, and reasoning loops have bounded detection and recovery. WebUI adds a project workbench for files, terminals, and Git. TUI and WebUI also gain model information, comparisons, and persona inspection, alongside improvements to skills, mobile session switching, and Windows reliability.

Changes

  • Interrupted-session recovery and team persistence: Streaming replies periodically save recovery records. Reopening a session preserves saved partial output and identifies the interrupted turn. Tools without recorded results are marked as having an unknown outcome and are not rerun automatically. This release is about rebuilding the architecture and the terminal UI: the runtime is rewritten in layers, every front end shares one runtime, and a session is a log of events that comes back whole; the new full-screen terminal UI is the default, with settings, models, MCP, plugins and background sessions in panels.

Changes

  • A new architecture: the runtime is rebuilt in layers (agent loop / capability assembly / coding runtime) and the old engine is retired; the terminal, web UI, VS Code and ACP share one runtime and behave alike. A session is now a log of events: undo, rewind and compaction are appended rather than rewriting history, so a session comes back whole after an interruption or a crash.
  • The new terminal UI is the default: running atomcode opens the new full-screen UI (switch back with --classic or [ui] screen); click, double-click a word, triple-click a line, right-click for a menu, drag-select across screens with auto-scroll, and click links and file paths to open them; the terminal title and tab show the session name and flag the session that is waiting for you.
  • Settings and management in panels: /config opens a settings panel (Settings / Config / Status / Usage / Stats) with quota, daily usage and per-model usage; /provider manages accounts and models and checks connectivity once saved; /mcp turns MCP servers on and off one by one; /toolbox toggles single tools mid-session; /plugin manages plugins; /status shows the signed-in account and when the subscription ends.
  • Background sessions and teams: /background (/bg) keeps the current session running in the background, grouped, switchable and retrievable; /review runs in the background by default; questions from background sessions come to the front to be answered in place; the team panel lists the main session, members and subagents with status, elapsed time and context use, and member sessions are saved and come back with their lead.
  • More reliable sessions: /resume previews what a session last talked about, and Ctrl+D twice deletes one; sessions survive renaming the project folder; double Esc opens the rewind panel; in a Git repository /rewind can take the code back too, on by default (ATOMCODE_CODE_REWIND=0 turns it off).
  • New and better commands: /changelog shows what changed in each release; /worktree creates a separate working copy and switches to it; /diff and /diff git show this session's and the workspace's changes; /loop 5m repeats on an interval; /todo add and /todo clear edit the plan; /cost itemizes tokens by model; /copy copies the last reply, /copy code the code blocks; /raw prints the whole conversation to the terminal for its own selection; !cmd runs a command locally; /cd keeps bookmarks and recent directories; the new UI also has /proxy, /schedule, /openrouter, /app, /webui and /sync, and /upgrade upgrades in place and restarts; the slash menu is ordered by how often you use each command.
  • Rebuilt model settings on the web: grouped by provider, one card for the provider and its models, connectivity checked once saved; set the reasoning effort levels a model offers and its default.
  • Models and reasoning effort: F2 / Shift+F2 switch models quickly, with effort chosen right after; /effort lists only the levels the model supports; GLM and Qwen reasoning is kept; when two accounts share a model name the status line says which provider; OpenRouter no longer sends you to the browser once authorized, and retired models drop off the list.
  • Smoother interaction: paste screenshots and image paths into the composer, with long pastes folded; file writes and edits show their diff inline; Ctrl+R searches this project's input history; Ctrl+X interrupts the turn and sends queued messages at once; sudo and ssh in tools ask for the password in the composer instead of hanging.
  • Security, stability, Windows, and fixes: reading credentials, keys or .env files asks for approval first; delegated subagents have clear limits; the repeated-call fuse is gentler and tunable with [coding] repeat_stop_rounds; images per request are capped and compressed so requests are no longer too large; legacy Windows consoles, colors, keys and box drawing work, and a console that cannot draw the new UI falls back to the classic one and says why; /upgrade on Windows no longer fails with "access denied" while an old version holds the slot; background processes in bash keep their output and stop reliably; switching to a strict provider no longer fails every request with 400.

v5.1.0（v5.2.1） 2026-09-18

Overview

This release widens what you can connect: the OpenAI Responses API and OpenRouter's free models, stronger AtomGit tools and code graph, plus opt-in code rewind and a daily work recap.

Changes

  • More providers: support for the OpenAI Responses API.

  • /worklog daily recap: sums up the day's work across projects into a short report.
  • Faster, smoother TUI, and fixes: the /resume list scans in parallel, about 4× faster; -c / resume only scans the current session's directory at startup.

This release improves selecting and copying in the terminal, adds a Zhipu Coding Plan preset and more hook events, and cuts the round trips weak models make on large files.

Changes
