MCP 集成

MCP（Model Context Protocol）是一个开放协议,把外部程序或 HTTP 服务的「工具」接到 AtomCode,让模型像调用内置工具一样使用它们。从 v4.20.4 起 AtomCode 内置 MCP 客户端,直接复用 Cursor 等同样使用 mcpServers 配置块的生态。

暂停本会话全部 MCP

在 /mcp 面板顶部点击“暂停全部”，或在列表页按 Ctrl+S；WebUI 的 MCP 菜单顶部也提供同样入口。暂停后工具不再提供给模型，连接会释放。“恢复”按各服务器原有配置重新连接，不会启用原本禁用的服务器，也不修改配置文件。

请先结束当前任务、goal/loop，收取后台任务并停止子 agent。暂停状态在同一会话内的模型切换和配置重载后保留；新建、重新打开会话或切换工作目录后重置，不作为持久化配置保存。

它能做什么

  • 通过官方 MCP server 操作 GitHub、GitLab、Jira 等外部服务
  • 接 Postgres / MySQL / DuckDB 等数据库
  • 使用文件系统、Playwright 浏览器、Slack 消息等社区生态 server
  • 把团队内部的领域工具暴露给模型,无需改 atomcode 源码

两个配置位置

路径作用域
<项目根>/.mcp.json仅当前项目可见,适合跟代码同仓库
~/.atomcode/mcp.json用户全局,跨所有项目共享

两份可同时存在;同名 server 以项目级为准(覆盖用户级)。仓库根目录的 .mcp.json.example 自带 stdio 与 HTTP 双模板和详细注释,推荐从它开始改。

配置 schema

顶层键固定为 mcpServers(旧键 servers 仍兼容)。每个 server 建议只写一种 transport:

  • stdio:command(必填)+ 可选 args、env、timeout_ms、disabled
  • HTTP:url(必填)+ 可选 headers、auth、timeout_ms、disabled

如果同一个 server 同时写了 command 和 url,当前实现会优先按 stdio(command)处理;为避免歧义,对外配置请不要双写。

字符串里支持 ${VAR} 与 ${VAR:-默认值} 的环境变量展开;敏感令牌不要写死,放到环境变量里。disabled: true 可临时关掉某个 server 而不删条目。

.mcp.json 还支持 JSONC 注释 —— // 行注释和 /* */ 块注释 —— 可以给某个 server 加说明或临时注释掉而不必删除。字符串值内部的注释符号(比如 URL 里的 //)会被原样保留。

所需扩展能力（可选）

在单个服务配置中，requiredExperimentalCapabilities 将后端明确声明的能力名映射到精确的正整数版本，例如：

"requiredExperimentalCapabilities": {
  "vendor/feature": 1
}

只填写后端文档明确支持的能力和版本。每次 MCP 初始化（包括 stdio 自动恢复）都会在连接可用前检查；缺失、格式错误或版本不同均拒绝连接。对配置了该要求的 HTTP 会话，未经重新初始化的会话 ID 变化也会被拒绝，需重连。省略该字段保持原行为。版本校验不会自动启用功能或协商其使用协议，不授予工具权限，也不能证明外部后端正确实现了其声明的策略。

stdio 示例(本地子进程)

{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/tmp"],
      "timeout_ms": 10000
    }
  }
}

HTTP 示例(远程端点)

{
  "mcpServers": {
    "github": {
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": {
        "Authorization": "Bearer ${GITHUB_TOKEN}"
      },
      "timeout_ms": 30000
    }
  }
}

GitHub remote MCP + OAuth

{
  "mcpServers": {
    "github": {
      "url": "https://api.githubcopilot.com/mcp/",
      "auth": {
        "type": "oauth",
        "provider": "github"
      }
    }
  }
}

首次使用前需准备 AtomCode 自己的 GitHub OAuth App client id,然后运行:

atomcode mcp add-github-oauth --global
ATOMCODE_GITHUB_MCP_CLIENT_ID=<client_id> atomcode mcp login github
atomcode

TUI 内也可在设置好环境变量后运行 /mcp login github,登录成功后用 /mcp reload 重连。

一行命令添加 server

atomcode mcp add 自动把 stdio 配置写入 JSON,不用手动编辑:

# 写入项目根 .mcp.json(默认当前目录)
atomcode mcp add playwright npx @playwright/mcp@latest

# 写入用户全局 ~/.atomcode/mcp.json
atomcode mcp add playwright npx @playwright/mcp@latest --global

# 指定项目目录
atomcode mcp add playwright npx @playwright/mcp@latest -C /path/to/repo

第一个参数是 server 键名(将出现在工具名里),后面跟可执行文件 + 参数。

GitHub remote MCP OAuth 可用专用入口:

atomcode mcp add-github-oauth --global
ATOMCODE_GITHUB_MCP_CLIENT_ID=<client_id> atomcode mcp login github
注意

同名会整段覆盖该 server。GitHub OAuth token 保存在 ~/.atomcode/mcp_auth.toml,不会写入 .mcp.json。

启动后会发生什么

模式连接行为工具出现时机
TUI后台并行连接,不阻塞界面每个 server 连上后陆续注册,可能略晚于首屏
单次执行(-p)启动时同步连接,等启用中的 server 尝试结束仅在至少拿到一批工具时挂载 MCP

TUI 下可在会话区看到 ✓ MCP server 'github' connected 或 ✗ MCP server '…' failed: …。单个 server 失败不会拖垮其他 server 与主程序。

图片结果

MCP 工具返回的内联 image 内容会与文字结果一起传入现有工具图片链路，供支持视觉输入的模型查看。支持 PNG、JPEG、GIF 和 WebP，保留原始图片字节和尺寸，不静默缩放截图。工具返回 isError: true 时仍保留其有效截图和错误标记。

图片会校验 Base64、声明的 MIME 类型、实际编码和像素数据。每张图片最多 4 MiB Base64，每次结果最多 4 张、合计 8 MiB Base64；单边最多 8192 像素，总像素最多 1600 万。请求级图片预算还可能进一步裁减历史图片。无效或超限时保留原文字、返回明确的工具错误，不附带部分截图，也不自动重跑已执行的操作；需要更小的截图时，应让服务端裁取目标区域。

此能力不包含桌面执行器，不会自动获取屏幕录制或辅助功能权限，也不会替换当前模型。文本模型不会因此获得视觉能力。暂不自动获取图片资源链接或将嵌入资源的 blob 作为截图使用。

隔离浏览器工作流

浏览器集成采用外部 Playwright MCP 后端。AtomCode 不捆绑 Node 或浏览器，启动时也不下载它们。请显式安装 Node 18+ 和 Chrome。目前仅有 macOS 本机验收条件；Windows、Linux 需要分别完成实机验收，不能视为已验证。

# 显式安装到仓库之外的自选目录
npm install --prefix /absolute/path/browser-backend @playwright/mcp@0.0.85
atomcode browser doctor --server /absolute/path/browser-backend/node_modules/@playwright/mcp/cli.js
atomcode browser enable --server /absolute/path/browser-backend/node_modules/@playwright/mcp/cli.js
atomcode

Windows 请使用绝对 Windows 路径；--node 可指定已安装的 Node 可执行文件。诊断仅检查版本，不启动 Chrome，也不能证明浏览器已安装。缺少浏览器时运行会明确报错，AtomCode 不自动安装。

/browser status
/browser doctor
/browser reload
$browser-use 打开本地测试页，填写已授权的表单并核对结果。
/browser disable
/browser reload

首次设置需在终端指定后端路径；设置后 /browser enable 可复用它。修改配置需要显式重载或重启。status 读取保存的配置，实时连接、项目覆盖和暂停状态请看 /mcp。自定义同名配置及修改过的技能会保留，不覆盖。

托管后端使用隔离 profile，关闭页面提供的 WebMCP，不连接个人 Chrome profile，不导入 Cookie。保留原生 MCP 审批（trust: false、空 autoApprove）；只读标记与工具级“始终允许”仍按现有机制生效。它们不等于站点授权，当前没有强制 origin 白名单。浏览器位于 MCP 宿主机器，不一定是客户端所在电脑。

托管 allowedTools 只暴露已审查的导航、观察、表单、交互和关闭工具，排除代码求值、不安全脚本、文件上传和浏览器安装工具。通用 MCP 也可配置精确原始工具名列表：省略表示不限，空数组表示全部禁止。发现、缓存和调用入口都检查该列表；它不授予审批，也不是操作系统或网络沙箱。

生成的页面快照和截图放在项目外的 <用户目录>/integrations/browser-use/artifacts。Unix 设置为仅所有者可访问，Windows 沿用目录 ACL。后端设置 16 MiB 输出清理目标，不是硬磁盘配额；禁用不会删除这些文件，不再需要时请自行清理。

通过 $browser-use 显式调用技能，安装后不会自动选用。截图任务需要视觉模型；结构化页面快照可供文本模型使用。取消和禁用不能撤销已发出的外部操作；结果未知时重新观察后再决定是否重试，只关闭本工作流拥有的浏览器资源。

CLI 操作 macOS 应用

可通过本地 Open Computer Use MCP 后端连接桌面。当前集成支持 macOS 14 及以上；截图任务需要当前模型支持视觉。AtomCode 不自动安装后端，也不额外启动一套模型代理。

# 显式安装固定版本后端（需要 Node.js / npm）
npm install -g @opensymph/open-computer-use@1.3.0

# 由你打开后端权限向导，为后端应用授予系统权限
open-computer-use doctor

# 无界面检查；权限齐全后才写入配置
atomcode computer doctor
atomcode computer enable
# 自定义安装位置：上述两个命令均支持 --executable /完整路径/可执行文件

在 macOS 系统设置中，为后端应用开启辅助功能和屏幕录制权限。atomcode computer doctor 只做有时限的无界面诊断，不会申请权限或抓屏；缺少权限时 enable 会失败，不写 MCP 配置或技能。它保留其他 MCP 项，拒绝覆盖同名自定义服务或技能，并关闭已知的前台输入与全局指针回退开关。

若后端报告了需要授权的 App，computer doctor 和权限不足提示都会显示其确切路径及 bundle identifier。请为这个 App 授权，Codex Computer Use 或其他副本的授权不会自动转移。旧后端未提供此信息时会明确显示 App 未识别，请先运行后端自己的 doctor 确认。

启用后重启 AtomCode，或在当前会话运行 /computer reload。明确的桌面操作请求（如“帮我在 Safari 窗口点击搜索按钮”）会自动加载已安装的 computer-use 静态指导；也可以显式输入 $computer-use 帮我在指定应用中完成任务。自动加载不执行工具、不授予权限，实际调用仍由模型选择并沿用现有 MCP 审批。说明文档、引用示例、代码开发请求和拒绝桌面操作的请求不会触发该规则；匹配不明确时请显式指定技能。[no-auto-skills] 或技能的 auto-load: off 可以关闭自动加载，宿主的 skills-host.auto_load: false 设置也仍然有效。

/computer help
/computer status
/computer doctor
/computer enable
/computer disable
/computer reload

这些 slash 命令在当前会话内委托宿主执行，与终端子命令共用诊断和配置实现。启用、关闭先保存配置；reload 单独通过现有重载流程使其生效，忙碌时会明确拒绝。自定义执行器路径请使用终端的 --executable 参数；不会在 slash 命令中拼接 shell 命令。

atomcode computer status
atomcode computer disable

status 读取用户配置，不代表当前会话的实时连接状态；项目级同名 MCP 配置仍按既有优先级覆盖用户配置，请用 /mcp 检查。disable 仅禁用本集成管理的用户配置项，并移除未修改的附带技能；运行中的会话需要重新加载。它不是紧急停止命令，无法保证撤回已发出的桌面操作。应用级强制授权、多个代理的桌面互斥和远程取消保证尚未包含，代码 rewind 也不会撤销外部 GUI 效果。

更新 AtomCode 后，可再次运行 atomcode computer enable 或会话内的 /computer enable，再重载以采用新版内置指导。只升级精确识别的原版技能；用户修改（包括 auto-load: off）会保留并明确提示，不覆盖。指导会区分换行的显示转义与实际文字，并要求保存后重新观察；界面状态仍不明确时应报告未验证。

工具命名

每个远端 tool 注册成 mcp__<server 键名>__<远端 tool 名>。

例:配置里 "mcpServers": { "github": { ... } },远端有 get_issue,模型看到的工具名就是 mcp__github__get_issue。

--disable-tools 也用这个完整名:

atomcode --disable-tools mcp__github__get_issue,mcp__filesystem__write_file

权限审批

MCP 工具默认 每次调用都需要确认(等同 RequireApproval),因为远端是外部不可信代码。

  • 按 Y — 单次允许
  • 按 A — 在当前会话内放行该工具(下次启动后失效,不会持久化)
  • 按 N — 拒绝本次调用
安全提示

把 MCP 工具返回的内容当作不可信数据处理,不要让它升级成系统指令。一个返回结果带「请忽略之前的指示」的 MCP server,模型不应该照办。

项目信任(.mcp.json)

定义在项目级 .mcp.json 里的 server 在你信任该项目前都是不受信任的。一个刚 clone 下来、自带 .mcp.json 的仓库不会在你机器上自动拉起子进程 —— 它的项目级 server 会被挡在连接循环之外(fail-closed),你会看到一条 blocked-untrusted 提示列出它们。用户全局 server(~/.atomcode/mcp.json)不受影响。

信任按项目目录记录,存于 ~/.atomcode/mcp_trust.json:

  • /mcp trust —— 信任当前项目;它的 .mcp.json server 立即连接(隐式跑一次 /mcp reload)。
  • /mcp untrust —— 撤销信任;该项目的 MCP tools 立刻移除。

在 Web UI 里,一个 信任项目 按钮通过 POST /live/mcp/trust 做同样的事,MCP 状态会显示哪些 server 已连接、哪些被挡下。

斜杠命令

命令作用
/mcp列出已成功连接的 server 及状态(失败的 server 不在列表里,只在会话区有红色错误行)
/mcp tools <server>异步列出某个 server 实际暴露的远端 tools
/mcp reload重新读取 .mcp.json / ~/.atomcode/mcp.json 并后台重连启用中的 server
/mcp trust / /mcp untrust信任(或取消信任)当前项目,使其 .mcp.json server 可以连接

当前限制

  • 仅支持 MCP 的 tools 能力;尚未实现 resources / prompts / OAuth / roots / elicitation
  • HTTP server 无指数退避重连,stdio 子进程退出后不自动重启 — 需用 /mcp reload 手动重连
  • tools/list 的 list_changed 通知不触发动态刷新
  • 工具结果只取 text 类型 content 块,image / resource 块当前忽略
  • [A] Always 仅当前会话生效,不写入任何配置文件
