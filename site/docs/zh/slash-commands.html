斜杠命令

在 TUI 输入框中以 / 开头即可触发命令,并获得自动补全菜单。按功能分类的 50+ 个内置命令如下;Skills 和 Plugin 加载的命令也会自动出现在补全菜单里。

核心功能

命令作用
/login推荐 — 一条命令完成 AtomGit OAuth + 申领 CodingPlan 免费额度 + 自动根据额度模型列表写好 provider 配置。首次启动最省事的入口;已登录后重跑会幂等地同步最新模型列表。v4.25.0 起 /codingplan 已折进 /login,旧入口已移除
/resume打开会话选择器,恢复任意一个之前的持久化会话(含消息、目录和模型状态)
/session创建一个全新的、干净的会话
/background · /bg同一条命令的两个名字,所有形态通用。不带参数:把当前会话放到后台并打开新的前台;带任务(/background <task>):在后台槽位直接启动一次性任务。子命令: list、<N>、drop <N|id>、help。详见 后台会话
/rename <新名字>重命名当前会话(影响 /resume 选择器里的显示名)
/provider管理供应商账号及其模型；支持预设供应商和自定义接口
/model设置默认模型 / provider，并切换当前会话；其他已打开会话不变
/cd切换到指定目录并开启新会话。也可直接输入 cd /path。

工具与实用操作

命令作用
/view · /view <文件路径>打开只读文件查看器。不带参数时打开一个模糊「仅文件」选择器(输入即筛选;像 ~/… 或 ./… 这类路径式查询还能打开项目之外的文件)。带路径则直接打开该文件。方向键 / PageUp-Down / Home-End(或 g/G 跳到首/末行)滚动;Esc 退回,Ctrl+C 退出
/undo · /undo N把对话记忆回退到上一轮(或第 N 轮)之前,并把那一轮的 prompt 还原回输入框;只回退记忆,不恢复磁盘文件
/diff显示当前工作目录未提交改动的 git diff(文件列表一次最多显示 5 行,并带「更多文件」滚动提示)
/review对当前改动做代码审查:/review 审查未提交改动,/review staged 审查暂存区,/review <base> 对比某个基准 ref
/paste从剪贴板粘贴图片(Windows 下 Ctrl+V 被终端拦截时的备用入口)
/cost按模型显示当前会话累计的提示、补全和缓存 Token。与 /usage 不同,后者查询的是 CodingPlan 网关的套餐额度
/context显示本轮上下文预算分解:系统提示、工具定义、冷区压缩、总消息数、context window 占用
/context prompt · /context personaTUI：查看当前组装的系统提示，或仅查看角色提示及追加设置；详见上下文与提示查看
/compact压缩历史消息,把早期对话压缩成摘要以腾出上下文预算
/rewind选择历史提示，并回退对话、代码或两者；详见 会话与撤销
/clear清空当前会话的消息(保留工作目录和模型)
/init扫描当前工作目录，按优先级创建或完善当前生效的项目指令文件（.atomcode.md、AGENTS.md 或 CLAUDE.md）。生成内容跟随当前语言，并可在 /config 中配置自定义提示词文件。
/background <任务>把任务派发给一个隔离的后台 agent(只读为主的工具子集),不污染当前主对话上下文。用于"顺手让它去查一下 X"这类轻探索。详见 后台会话
/worktree <子命令>Git worktree 隔离:create 在新分支上拉一份独立 worktree、list 查看现有 worktree、done 仅切回主检出（不提交、不 squash、不合并）、cleanup 删除 worktree（不验证是否已合并；请先提交并合并需保留的成果，--force 会丢弃未提交内容）
/todo · /todo add <任务> · /todo clear重新打印当前待办清单 —— 从会话记录里派生(定位最近一次 todowrite 工具调用并重渲染),带「进行中 / 已完成」状态标记。/todo add <任务> 确定性地追加一条任务(不走模型);/todo clear 清空清单。清单是无状态派生的,不额外落盘;模型执行长任务时会自己维护它,你也可以随时用此命令查看进度
/copy把上一条回复复制到剪贴板:/copy 复制整条回复的 markdown 原文(整个回合,不含工具输出);/copy code 复制最后一个代码块、/copy code N 复制第 N 个、/copy code all 复制全部代码块(旧写法 /copy N、/copy all、/copy msg 仍可用)
/save把当前会话导出成 markdown 文件:/save 用自动生成的文件名,/save <文件名> 指定文件名
AtomGit Issue 现在由内置工具处理

/issue 已移除。执行 /login 后，直接用自然语言提出需求即可，例如“为这个 Bug 创建一个 AtomGit Issue”。AtomCode 会选择内置的 atomgit_issue 工具，写操作仍需权限确认。详见内置工具。

只读报告可在回合中运行

不必等回合结束就能查看状态:/status、/diff、/cost、/usage、/rename 在 agent 流式输出时也能运行。它们以输入框下方的临时面板呈现(按 Esc 关闭),不打断进行中的回合。/usage 在回合中还能在 Current / Overview / Models 视图间按 Tab 切换。

质量检查策略

/quality on 开启、/quality off 关闭；/quality status 查看当前状态，/quality evidence 查看最近一次证据。策略与 Build / Auto 等审批模式独立，检查命令仍遵守原有权限。修改策略时需处于空闲状态。

先在用户配置中明确指定检查命令（以下仅为示例，请换成项目实际命令）：

[quality]
# 默认关闭；也可用 /quality on 在当前会话开启
enabled = false

[[quality.gates]]
name = "tests"
command = "npm test -- --run"
timeout_secs = 120

[[quality.gates]]
name = "types"
command = "npx tsc --noEmit"
timeout_secs = 60

配置加载后，普通任务产生改动时，交付前按顺序运行所有检查。全部检查成功且检查期间文件未再变化，才显示 Quality Passed。失败、拒绝、超时、取消或证据保存失败不会通过；文件保留，不自动回滚或提交。后续修改文件后，/quality status 会将旧结果标为 Stale。没有改动的任务标为 NotRequired，不宣称已经测试。

确需接受未通过的结果时，可在任务停止后运行 /quality waive <原因>。它新增一份人工豁免记录，保留原始失败证据，显示 Waived 而非 Passed，也不会关闭后续任务的质量检查。检查结果只证明配置命令对记录的文件版本执行成功，不保证没有 Bug。

第一版仅支持有初始提交的本地 Git 工作区和普通前台任务，开启时不能启动 goal / loop、团队委派或后台命令。快照覆盖版本控制中的文件和未被忽略的新文件，不覆盖忽略的构建产物或外部服务；子模块不在支持范围内。单项检查限时 1–300 秒；快照最多 256 MiB 文件内容，单文件最多 64 MiB，diff 最多 32 MiB，超过限制会拒绝验证。证据保存在用户数据目录的 quality-evidence/，包含文件指纹、diff、命令、真实退出码、耗时和输出，可能含私有代码或敏感日志，请谨慎分享。重启后开关以配置为准，已保存证据仍可查看。

上下文与提示查看

/context 显示上下文预算与占用统计。在 TUI 中，/context prompt 显示当前加载组件组装出的系统提示正文，/context persona 只显示角色提示及其追加设置。

系统提示正文不等于完整模型请求：工具定义和对话历史另算。提示正文查看入口以上述 TUI 命令为准，WebUI 的 /context 只提供预算统计。关于正常压缩时的保护范围，以及恢复后提示为何可能变化，见 会话提示保留策略。

对话模式与思考

命令作用
/plan切到 Plan 模式:只读探索,模型可以调用 read_file / grep / list_directory 等不写盘的工具,但 edit_file / bash 等会被屏蔽。适合在动手之前让模型先理清方案
/build切回 Build 模式(默认):全部工具可用,可以读、写、执行。/plan 和 /build 之间可随时来回切
/goal <目标>设定一个完成目标,让 agent 自动循环——一轮接一轮——直到目标达成。/goal(无参数)查看当前目标与轮数,/goal clear 停止
/loop <间隔> <prompt 或 /命令>按固定间隔重复执行一个 prompt 或斜杠命令。例 /loop 5m /diff 每 5 分钟跑一次 /diff;/loop 30s 检查一下构建 每 30 秒发一次该 prompt。间隔单位 s/m/h,范围 10s–24h
/loop <prompt>不带间隔时进入自定节奏模式:任务交给模型,由它自己决定何时进行下一轮,适合「盯着某件事直到收敛」这类不好用固定周期表达的任务
/loop · /loop stop/loop(无参数)查看当前循环状态;/loop stop(或 off / clear / cancel)停止循环。/loop 与 /goal 互斥,设定其中一个会自动取消另一个
/think on / off开关 extended thinking(对支持的模型 — Claude / DeepSeek-R1 / GLM-4.5 等)。开启后模型会输出推理过程,代价是更慢更费 token
/think budget <N>给 thinking 设个 token 预算上限(对 Claude 系列生效),控制推理长度
/effort <high|max|off>DeepSeek 推理努力控制——在 DeepSeek 模型上用更多延迟/token 换取更深的推理

团队面板

命令作用
/team · /team toggle展开 / 收起团队面板(切换)。收起后只留一行表头,成员行不再绘制,键盘焦点也不再落到它们上面
/team show · /team open展开团队面板。没有成员也没有后台任务时回执「当前没有团队成员或后台任务,暂无可展示的团队面板。」
/team hide · /team fold · /team close收起团队面板(成员照常在后台继续,不取消任何成员),回执「团队面板已收起。」
其它参数拒绝并回显用法 —— /team 只认这三态(status、clear 等不在其中)

三个子命令都只改显示:回执以提示行出现、约 5 秒后消失,不写进会话记录,也不调用模型;它们不会启动、取消或等待成员。面板表头给出成员数与后台任务数,成员行标注它被要求做什么、已运行多久与上下文占用;成员由 agent 通过 team 工具委派产生(多成员并行、各带角色与 scope)。另见 子代理(task 工具的短生命周期子任务)。

永久记忆

命令作用
/remember <内容>记一条到项目级记忆(默认作用域,绑定当前工作目录)
/remember --global <内容>记一条到全局记忆(所有项目共享)
/forget <关键词>删除全局 + 项目记忆中含该关键词的所有条目(大小写不敏感)
/memory查看当前生效的所有记忆,按 [Global] / [Project] 分组

详细使用与最佳实践见 永久记忆。

扩展生态

命令作用
/setup第一次执行时,把内置的 atomcode-automation-recommender skill 解压到 ~/.atomcode/skills/,在项目 .gitignore 追加 .atomcode/local/,并写 .atomcode/setup-state.json(signals 哈希 + atomcode 版本 + 已安装列表),全程持项目级锁。然后自动调用 recommender skill — 它会扫描项目(语言、框架、已有 hook 等)、联网检索并推荐适合该代码库的其他 atomcode skill 安装。后续执行会跳过 seed 安装、直接重跑 skill。命令后跟的文字会作为 steering 传给 skill,例如 /setup 重点关注测试。CLI 形式 atomcode setup --force 会按内容哈希强制重装 seed 文件
/skills浏览当前已加载的 skills(项目级 + 用户级)。每个 skill 也会以独立的斜杠命令形式出现在补全菜单里,可以直接 /<skill-name> 触发
/plugin打开交互式插件管理器,可浏览 marketplace、安装/卸载插件、添加/移除 marketplace
/plugin marketplace add|remove|update|list管理 marketplace 注册(add 克隆 git 仓库,remove 移除,update 拉最新,list 列出)
/plugin install <plugin>@<marketplace>从指定 marketplace 安装插件
/plugin uninstall <plugin>@<marketplace>卸载已安装的插件(保留 marketplace 注册)
/plugin list列出本地已安装的插件
/plugin reload重新加载所有插件(扫描磁盘变更、刷新 skill/hook 注册)

详细配置与使用见 Skills 扩展 和 Plugin 系统。

插件可以注册自己的斜杠命令。例如官方频道插件会新增 /wechat(显示 AtomCode 微信用户群二维码):

/plugin marketplace add https://atomgit.com/atomgit_atomcode/AtomCode-Channel
/plugin install weixin@atomcode-channel

MCP 集成

命令作用
/mcp列出已成功连接的 MCP server 及其状态(连接失败的 server 不在此列表,只在会话区有红色错误行)
/mcp tools <server>异步列出某个 MCP server 实际暴露的远端 tools(若超时/失败会提示)
/mcp reload重新读取 .mcp.json / ~/.atomcode/mcp.json 并后台重连所有 server

详细配置与使用见 MCP 集成。

WebUI 与同步

命令作用
/webui启动本机浏览器并生成手机中继二维码，无需组网；--local 仅本机。当前 TUI 会话自动实时同步
/webui --host <addr>把服务绑定到指定地址;/webui lan 等价于 --host 0.0.0.0(暴露到局域网)。可用的局域网访问地址会同时显示文字链接和二维码，手机扫码即可打开。跨网络访问使用默认 /webui 的中继二维码,见 远程访问指南
/webui stop关闭 webui 服务
/sync把当前 TUI 接入正在运行的 webui 会话(需先 /webui)。两端实时双向同步,多个浏览器 / 终端可同时围观同一会话
/sync off退出同步,回到独立会话
/app把当前会话通过官方中继暴露给 手机 App:终端里直接吐出一个二维码,用 App 扫码即可配对,在手机上实时查看并接管这段对话(与 /webui 同源共用同一段会话,双向实时同步;区别是 App 扫码配对，不打开浏览器)。支持在 App 内处理权限审批；连接恢复后会同步仍待处理的审批。App 断线不会自动取消电脑端任务。需先 /login 登录。中继连接与重试日志保存在产品目录的 logs/app-relay-<进程号>.log（默认 ~/.atomcode/logs/）
/app stop停止 App 远程访问,断开中继并回到本地会话

详细见 WebUI 界面 与 远程访问指南。

配置与帮助

命令作用
/status显示登录状态、当前 provider、模型、上下文预算、CodingPlan 用量和重置时间
/whoami显示当前 AtomGit 登录用户的用户名 / 邮箱
/config显示 ~/.atomcode/config.toml 的路径
/reload从磁盘热加载 ~/.atomcode/config.toml,不需要重启 atomcode 就能让外部修改(或另一个终端的 /login 带来的变更)生效
/proxy切换出站代理模式:跟随系统代理(默认)/ 指定固定代理 / 直连不走代理。适合公司代理网、需要强制走某个代理或强制直连等场景,选择会写回配置
/language切换界面语言:自动检测(LC_ALL / LANG)、English、或 简体中文。立即生效并写回 ~/.atomcode/config.toml
/welcome重新打开 3 步首次启动向导(欢迎页 → 语言 → 接入方式)。会话非空时会先弹 y/N 二次确认,确认后清屏。语言和默认接入方式都可以从这里再调一次
/logout清除 AtomGit OAuth token
/upgrade自动升级到最新版本;子命令 /upgrade rollback 回滚到上一个版本
/guide内置上手向导:/guide 列出可问的主题(快速开始、换模型、MCP、Skills、记忆、后台任务、上下文、快捷键、配置),/guide <主题> 直接在对话里讲解(首次会自动安装 atomcode-skills 插件)
/help展示所有可用斜杠命令的列表
/keys展示键盘快捷键参考(分组列出输入 / 历史 / 会话 / 弹层导航,并标注 Shift+Enter、Alt+Enter 在不同终端的兼容性)。详见 键盘快捷键
/quit · /exit退出 atomcode(也可以连按两次 Ctrl+C)

命令使用技巧

  • 自动补全 —— 输入 / 后会立刻弹出补全菜单,用 ↑↓ 选择,Tab / Enter 确认。
  • 模糊匹配 —— 补全支持子串匹配,比如输入 /prov 就能命中 /provider。
  • 打断正在进行的操作 —— 模型正在流式输出时按 Esc 可以打断,然后再输入新的命令或 prompt。
  • Skills 也会出现在菜单里 —— 当你在 Skills 目录中添加了自定义命令后,它们会以相同格式出现在补全菜单里。
