# 无工具长等待与异常统计复核（2026-10-27）

## 结果

没有证据宣告用户的设计质量问题已经修复。新的原生样本仍有过度设计、只打印工具调用文本，以及长时间持续思考但没有正文。工具目录关闭/执行拒绝继续有效。没有自动解析执行 DSML 文本，也没有更改全局推理强度、模型或超时默认值。

## 原生测量

使用已固定的无工具修复二进制，SHA256 `0d4ceb27ce58e503fa3041b44a372e48a3578a80b06d115eb2e7a3dbcbde68fb`。每次独立临时产品目录和项目，同一自然两表设计问题，工具目录经 wire 记录为空，静态 gateway/model 别名 deepseek-v4.1-flash-1017。上游请求保留原生输出上限32768，比较 omitted 和 max；每次外部测试限时120秒。正常配置未被修改。未持久化模型 private reasoning，只有接收字符数量与时间。

| 样本 | 结果 | 可见现象 |
|---|---|---|
| omitted，第1次 | 39.9秒完成请求 | 3225字符设计，仍引入 epoch、窗口与额外时长。主请求 timing 未完整落盘，不拿辅助请求时序代替主请求。 |

“完成请求”不是质量通过。后两项是为了修复测量后重新取时序，不是选择性重跑找通过结果；四个样本全部保留。单次/少数样本、后台权重与计算档位未被 attested，不能归纳 max 必然更慢/omitted 更好，也不能决定改默认值。该120秒是测试脚本限时，不是产品600秒的复现。

新的长等待样本证明存在“持续返回思考但未产出正文”的具体情况，不能都归因于启动卡住或网络没回应；没有原用户对话仍无法断定原案原因。原生进程 exit0/正常 turn terminal 也不能把裸工具调用文本算成设计回答。

## 修正评测代理

发现 Relay 收到 SSE `[DONE]` 后仍等上游 HTTP EOF，导致主请求可见完成后其记录尚未落盘。现按明确 SSE 终态关闭转发，记录 headers/首 body/首 reasoning/首 text/字符数，并可在测试限时保存在途记录。新增纯本地回归：上游在 `[DONE]` 后故意保持 HTTP body 未结束，代理必须及时结束。27项离线测试通过。未修改产品网络代理。

旧测量工件仍保留，不补造缺失主请求时序；不能把其仅有的 bootstrap/sidebar 请求时序拿来解释正文生成。

## 修复失败终态丢失已收到 usage

复核前轮 provider 保护发现：网关已发送 usage，但 content_filter、未知终态、工具片段上限或无终态 EOF 会直接返回 Error，丢掉 decoder 缓存的 usage。新增回归修复前失败：已收到 prompt=11/completion=5，结果只有文本/工具片段/Error，没有 Usage。

修复在同一解码器内，先发一次已收到的 Usage，再发 Error；不发 Done，不执行缓存工具，不增加重试。消费者遇 Error 会停止读取，所以顺序有实际意义。没有上游用量时不虚构，也不把 usage 当作实际账单证明。EOF 与非正常终态统一遵守。

验证：1096项 capabilities 单元、17项 HTTP/压缩集成、27项脚本离线测试通过；格式与 diff 检查通过。全仓及 feature 编译门通过。生产 persona 未修改，本轮不把统计完整性修复说成设计质量修复。其他会话正在修改 webui/relay 的 dirty 文件，保持原状，不纳入本任务的行为修改。
