# Native tool opt-out regression probe

`no_tools_probe.py` requires Python 3 and an already-built AtomCode binary. It
uses a temporary product home, temporary project, and loopback fake provider.
It never calls a real model or uses production credentials. The only readable
fixture is generated by the probe and removed with its temporary directory.

```sh
python3 evals/design-convergence/no_tools_probe.py \
  --binary target/release/atomcode --output /tmp/no-tools-catalog.json
python3 evals/design-convergence/no_tools_probe.py \
  --binary target/release/atomcode --output /tmp/no-tools-blocked.json --attempt-tool
python3 evals/design-convergence/no_tools_probe.py \
  --binary target/release/atomcode --output /tmp/tools-enabled.json --attempt-tool --with-tools
```

The first check requires an empty published catalog. The second additionally
has the fake provider request `read_file` even though no tools are published;
the fixture must not reach the model. The third is a positive control: normal
tool mode must publish tools and successfully return that same fixture.

A passing probe exits zero; timeouts, setup failures, and contract violations
must not be counted as passes. JSON output contains tool names, a binary hash,
and whether the fixture was visible, rather than request bodies, credentials,
or file contents. These are implementation checks, not model-quality tests.

The Rust companion regression in `atomcode-coding/tests/runtime_criteria.rs`
covers provider swaps, capability reloads, config rebuilds, and directory changes,
including a host layer that explicitly tries to include a tool.
