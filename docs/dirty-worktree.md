# 任务开始前的工作区提醒

coding 运行时在主 agent 的真实用户输入第一步，只读检查当时的 Git 工作区。
发现暂存、未暂存或未跟踪改动时，会把一条提醒作为该回合的上下文写入会话事件日志，
在模型首次请求之前送达：这些是任务前已有的改动，可能来自用户或其他 agent，不能假定
归属，更不能为了获得干净工作区就自行 checkout、restore、reset、clean 或 stash。
要求丢弃或移动已有改动时，用户仍需明确指定操作和范围。

这是提示机制，不是文件锁、备份或强制阻断。现有工具风险分类、授权模式与审批规则没有
改变；尤其不会新增弹窗、自动 stash、自动提交或自动清理。只有能够确认属于本任务的
编辑才可针对性撤销，不能因为改过一个文件就回滚该文件中的全部改动。

检查与快照的关系：

- 会话开始的系统 Git 快照仍是冻结快照，恢复会话时不重写其已保存内容。
- 新用户输入会重新检查当时状态，因此会话开始后在编辑器产生的改动也可触发提醒。
- 每个输入只在第一步检查，不在同回合的每个模型请求或工具调用前重复运行。
- 干净工作区和非 Git 工作区不添加这条提醒；失败、超时或输出超限时，只提示状态未知，
  不伪装成干净。原有启动快照中，Git status 读取失败也改为显示未知。
- 内部续跑、团队成员及 task 子 agent 不重复添加主会话的这项检查。
- 恢复后的新输入会重新观察，提醒标明回合号；旧提醒只说明当时的状态，不是当前实时状态。

Git 探测总超时为 2 秒，单路输出上限为 64 KiB，禁用可选索引锁及 fsmonitor。
新提醒不包含文件名、diff、凭据或 Git 的原始错误输出。大仓库中探测可能超时，模型应在
后续需要修改或执行 Git 操作时重新检查实际状态。先前干净也不意味着后来仍干净。

`stash drop/clear` 和 `restore -s/--source` 的风险识别修复不属于此变更，需单独处理。
