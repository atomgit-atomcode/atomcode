# Provider 流式空闲超时续接

基线：release/v5.2.3，8db380ae4。修改前工作区无 tracked 修改。

## 根因与边界

OpenAI 兼容、Responses、Anthropic、Ollama 的字节流空闲超时只提供错误文字，未提供现有恢复行要求的错误码。正文已输出时无法进入保存进度续接。

kernel 流协议定义中立 STREAM_IDLE_TIMEOUT_CODE。capabilities 的四个 provider 共用错误构造；harness 保留既有常量名称作为同一码的别名，使用现有恢复行；独立 kernel 使用已有续接分支并正确报告 Timeout。

恢复由既有运行时路径持有，不新增生命周期 owner、hook 或恢复状态机。不修改超时数值、普通重试次数或持久化格式。未完成工具输出、HTTP 拒绝、无安全正文或已完成结果时不授权续接；已有一次续接预算与连接中断共用，支持既有取消。

## 对照与验证

本地 OpenCode 按输出进度区分重试与续接，Codex 使用流错误统一重试，OMP 保存正文后注入提醒有限续接。本产品保留原有更低的续接预算。

测试覆盖真实 HTTP 响应已输出正文后保持连接但无新字节、发布装配正文与工具恢复、工具片段拒绝、重复空闲失败停止及独立 kernel。超时等待使用虚拟时钟；HTTP 开连接阶段恢复真实时钟，收到正文后暂停。
