# 明确摘要请求失败的原因

截图版本 5.2.7/dd97065f 早于分段摘要与输入预算修复；截图不能确定具体服务端错误。
原实现将多种非瞬时 provider 错误统一显示为摘要失败，导致重试与模型切换缺少依据。

沿用现有 CompactionDiagnostic 展示通路：区分 401/403 鉴权或权限失败、
400/402/404/405/415/422 请求被拒绝、429 限流。日志仅增加数字 HTTP 状态码，
不输出响应正文、错误消息或凭据。明确的请求拒绝即使被错误标记 retryable 也不自动重试。
上下文溢出仍由既有缩窗路径处理；保留历史、不提交失败摘要的规则保持不变。

不改变 runtime/session owner，不新增持久化事件字段或压缩状态机。
验证结构化错误分类、拒绝不重试、中文/英文共享展示，以及相关编译与格式门。

验证结果：相关四个 crate 的 nextest 2,673 通过、1 跳过；完整编译门、格式与 diff 检查通过。使用模拟 provider，未连接截图中的 Windows 模型服务。
