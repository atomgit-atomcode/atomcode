# 安装文件更新后的运行进程提示

日志显示，报错进程从 10 月 16 日持续运行到 26 日；用户通过外部命令查询的构建日期晚于进程启动日期。运行中的进程不会因为磁盘二进制被替换而自动加载新代码。

已有路径：TUI `/upgrade` 安装后记录 Restart，请求正常退出，在终端恢复后交由 launcher re-exec。用户因后台任务选择继续留在 TUI 时，重启可以被推迟。外部 `atomcode upgrade`、安装脚本或包管理器不掌握当前进程的 live session，不能强制结束它。后台预下载仅准备升级，启动时应用，是另外一个阶段。

本次处理外部替换和推迟重启的可见性：

- 宿主捕获初始安装路径和文件身份；优先使用经 canonicalize 验证属于本进程的调用路径，保留包管理器的稳定符号链接。基线是进程级事实，不因 provider/session remount 而刷新。
- TUI 通过现有 UpdateCheck 宿主接口每 60 秒检查本地变化；网络更新查询仍只在启动时进行。UI 通道关闭后监视任务停止，包括本地检查尚未返回的情况。联网查询与本地监视并行，晚返回的“可升级”结果不得覆盖已安装后的重启提示。
- 安装文件变化时，在对话区显示一次完整说明（使用“旧版本”表述，具体版本和构建号仅写日志），底部保留简短提示。底部空间不足时仍有对话区消息可读。临时缺失或不可读的文件不判定为更新。
- 保留正常退出、任务保护和现有退出恢复命令；不终止其他 PID，不热替换 agent 或运行时，不自动重新提交用户任务。
- 启动日志记录 running_version（含构建号）和 process_id，避免再次把磁盘 --version 当作旧进程版本。

检测依据是文件身份、大小和修改时间，不执行候选二进制，不猜测更新后的版本。重装和回滚也可能触发提示。用户当前已运行的旧程序无法获得尚未加载的新监视代码，因此首次仍需正常退出并启动修复版本。

覆盖：真实文件替换、更新窗口内文件缺失、包管理器符号链接切换，以及既有升级/回滚与 TUI 回归。监视不引入新的 runtime/session owner。
