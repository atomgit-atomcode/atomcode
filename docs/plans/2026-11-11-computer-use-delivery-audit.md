## Delivery priority after scope review

The user asked whether a general Computer Use capability is sufficient for the first delivery. Prioritize the existing common MCP/runtime path, explicit CLI/TUI setup, screenshots and basic input, ordinary approvals, cancellation and owned-resource cleanup. Do not start further upload/authentication/permission-matrix extensions while the basic native desktop workflow still lacks actual GUI acceptance. Preserve existing extensions and their tests; they do not substitute for that acceptance.

The next acceptance target is one supported execution host: discover tools, capture a real screenshot, click/type/scroll in a disposable test application, observe the resulting screen, exercise denial/cancellation and confirm cleanup. Reuse the existing runtime owner and backend contract. Other platforms and the complete browser policy matrix remain separately recorded unfinished work; this priority change does not establish their completion.
