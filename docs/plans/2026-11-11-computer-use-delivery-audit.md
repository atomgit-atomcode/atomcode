Inline terminal raster painting is optional enhancement, not an additional completion condition from the approved design, which requires image indication and retrievable details. The existing graphics implementation remains a static mascot slot; no general inline screenshot capability is claimed.

The reproduced cold-launch actor warning is corrected and verified by old-App-fails/new-App-passes acceptance; see [launch correction](2026-11-11-native-launch-callback.md). Next required work remains execution policy and platform/GUI acceptance. Only the user can grant the exact App's OS permissions; a Codex Computer Use grant does not transfer to it. The overall objective is not complete.

The attempted per-origin download event gate was rejected before release after an actual completed-download counterexample: cancel returned success while upstream auto-save persisted the denied synthetic payload. [ADR 0032](../adr/0032-origin-downloads-remain-backend-owned.md) and the opt-in characterization verifier preserve the execution evidence and choose an owned artifact-publication boundary for further transfer work. The production v1 backend is byte-identical to c86fb5425; its 13 unit tests and nine real Chrome groups pass again with zero forbidden connections. This is progress in resolving the execution design, not completion of the upload/download/CDP matrix or permission to accept unsupported allow settings.

The first [controlled publication unit](2026-11-12-controlled-browser-downloads.md) now implements and tests a backend-owned HTTP(S) publisher: permission checks before each dispatch, bounded complete responses, private staging, generated exclusive publication, cancellation and awaited shutdown without retries. It is deliberately not exposed as an MCP tool yet. This does not enable per-origin download allowances; transport cancellation, authenticated browser-context behavior and managed policy-v2 integration remain open.
