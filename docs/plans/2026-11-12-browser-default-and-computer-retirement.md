# Browser default and built-in desktop retirement

Baseline `release/v5.2.7`, `443d725f4`, initially clean. User explicitly requested removing the built-in `/computer` integration and then required browser capability to work automatically. This supersedes the previous native desktop delivery plan; historic desktop plans remain evidence, not current product requirements.

Keep CodingRuntime as the only coding lifecycle owner and native session logs unchanged. Remove CLI/TUI `/computer`, its Host API command/action, managed native setup/skill, desktop-specific tool grouping, experimental turn-scope wire extension, native integration sources/patch/build/package/GUI/portable harnesses and their dedicated tests. No alias, compatibility handler or backend fallback should remain. Do not uninstall the user's test App, alter system grants, rewrite user MCP configuration or erase session history. Advanced users may configure external desktop tools using standard MCP.

Browser setup reuses an independently named host-local MCP document lock, optimistic file writes and diagnostic-process group cleanup. Preserve ordinary MCP initialize, tool discovery, capability requirements used by the browser origin backend, approvals, cancellation guards, unknown-result no-replay, awaited retirement of abandoned transports before turn terminal, and inline images. Rename the former scope-finish seam to generic finish_turn without scope identities or proprietary acquire/release messages; retain captured-client replacement protection. No persisted format change or importer is needed.

After explicit one-time browser setup, install browser-use guidance with `auto-load: browser-use`. The existing skills-host pre-turn seam recognizes clear browser/webpage/URL operation requests and loads static guidance without executing embedded commands or inheriting allowed-tools grants. Ordinary connected MCP tools remain model-visible. Native app requests, coding/debugging questions, quoted/code examples, explicit skill/browser opt-out and disabled automatic loading must not trigger browser guidance. A no-submit constraint on an otherwise requested web operation does not disable safe guidance. Missing dependencies/connections or paused MCP are explained, never silently installed, enabled or unpaused. Existing sessions still use explicit reload after configuration changes.

Upgrade only the exact previous bundled browser skill (including its prior opt-out frontmatter) or the older recognized bundled version; preserve customized guidance. Test ordinary-language requests through the actual Host/CodingRuntime and external browser backend, including approval denial with zero HTTP effects. Keep real-model reasoning distinct from a scripted provider's native integration evidence.

Validation pending: crate tests for capabilities, coding/harness, TUI/i18n, host API and CLI; actual browser workflow regression and automatic-guidance native acceptance; format, full workspace compile gate, product-directory/layer checks and Cargo.lock audit. Check current production references before claiming the desktop surface retired.
