# HTTP 建立请求恢复

HTTP 客户端仍由各 Provider 持有，不向 runtime 增加第二套网络状态。

OpenAI 兼容与 Responses 共用 open_stream；Anthropic 使用同样的预算 helper，并保留自身客户端构造策略。单次响应头等待不变，所有 OPEN 尝试及退避合计最多两倍 open_timeout，预算耗尽返回不可自动重试的 OPEN_TIMEOUT 错误。静默超时后，有剩余重试次数时最多重建一次连接池。收到响应头后退出此预算，不限制正在输出的流。

日志复用 tracing 的 atomcode.log，记录阶段、次数、预算、状态码和超时后是否刷新连接池；不记录 URL、凭据、会话内容。

验证包含虚拟时钟的总预算断言，以及本机 HTTP 服务第一次保持静默、第二次响应成功的恢复断言。回环服务测试使用真实时钟，以避免 Tokio 虚拟时钟在操作系统网络就绪前推进。鸿蒙实际复现仍需用户验证。
