# 下载等待策略与展示

用户观察到模型反复执行 `sleep; ls; pgrep` 等待 SDK 下载，每次产生独立工具记录与模型请求。

## 当前实现与边界

- CodingRuntime 已拥有显式 `bash_start(notify_on_exit=true)` 完成观察；取消、替换与策略干预会撤销观察，不接管进程生命周期。
- TUI 已按同一 turn、目录与 job_id 合并相邻的无输出运行中 bash_poll；新输出、错误、结束与正在执行的调用独立显示，记录可展开。
- 普通 bash 命令没有可靠任务关联；不通过命令标题或任意 shell 文本推断任务身份，也不把文件存在、进程消失当作成功。

## 本次修改

由实现通知能力的 capability-commands 宿主行贡献等待策略：有终点的下载、安装、构建和测试优先显式请求通知，执行真实命令后让出当前回复，收到通知再取输出和验证结果。避免循环 sleep / ls / pgrep / 空轮询。服务器与 watcher 不启用完成通知。已经启动的无通知任务继续沿用已有 job，不重启或假称接管未跟踪进程。

不修改持久化协议、默认参数、运行时状态机或已有 TUI 分组规则。已有历史 shell 轮询不会因此自动合并。该修改改善模型执行引导，不能保证所有模型遵从，实际请求量下降需新会话验证。
