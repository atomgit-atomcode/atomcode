# 在 WebUI 中开启远程访问

用户反馈：普通 `/webui` 打开本机网页后，远程访问弹窗不应要求用户回终端执行 `/webui remote`。默认不启动中继与网页能主动开启中继是两个独立行为。

交互：打开弹窗只查询状态；用户点击“开启远程访问”才启动中继，期间禁用重复点击，成功后在当前弹窗显示中继地址和二维码。失败显示实际原因并允许重试。已有中继直接展示；局域网地址可继续使用，同时允许开启中继。不支持宿主回调的独立 daemon 保留终端引导。

所有权：CLI 在现有 WebUI 实例中注册一个仅驻内存的异步启动回调，复用现有 tunnel owner、启动串行锁、超时与取消代际。daemon 不下载或管理 relay 子进程，也不创建第二运行时。回调随 WebUI handle 退役，注册时校验实际实例端口和 token。凭据不进配置或自描述。

接口：受已有鉴权保护的 `POST /tunnel/start`，只接受空 JSON 对象，不接收客户端指定的目标地址或凭据；GET 状态无副作用。新增能力字段告知前端宿主是否可启动中继。命令与网页共用启动函数，结果统一存入既有 relay_url，网页继续通过 `/tunnel/status` 展示原值。旧链接格式兼容修复保留。

验证：拒绝未授权、非 JSON、自定义目标输入，验证宿主回调调用和返回地址；无宿主返回明确不支持。浏览器使用虚构地址验证连接中、成功、失败以及移动端宽度，不连接真实中继或重用截图凭据。
