## Native runtime follow-up

Baseline `b922da55f`, with unrelated WebUI edits preserved. Reviewed the current Host connection helpers, scripted provider, managed computer setup, MCP adapter risk rules and their recent history. This adds an opt-in acceptance criterion in the existing Host test suite, not a runtime owner or protocol. CodingRuntime owns the agent; its existing MCP registry owns the backend connection and ordinary approval/cancellation. Tests use an isolated product directory, a separately built fixture and explicit absolute backend/fixture environment paths. Stock read-only hints remain safe under the existing policy; mutations require per-call approval. A denied or pending-cancelled mutation must produce no ToolStarted and no fixture changes. Images must cross the native ToolResult seam. No full-display capture, unrelated input or helper-wide shutdown is allowed.

The first trial exposed an incorrect assertion in the new test: it expected approval even for read-only list/screenshot calls. The existing MCP adapter intentionally classifies read-only hinted tools as Safe. The test assertion was corrected to check the current intended policy; production approval behavior was not changed. Actual desktop results are recorded below after the follow-up run.

The runtime trial then found a genuine result-boundary issue: the backend repeats its PNG as a data URL inside JSON metadata and as an image content block. The native output budget truncated the large textual copy, breaking JSON before later screenshot metadata. Correct this at the existing MCP result conversion boundary: only valid JSON string values exactly equal to an already validated attached image data URL are replaced with an explicit attached-image label. Window IDs, screenshot IDs, geometry and accessibility text remain in JSON; original image bytes and validation/budgets remain. Unrelated URLs, text-only results and rejected image sets are not rewritten. The acceptance reader consumes the first JSON value because the existing converter appends a human-readable image-dimensions line. No frontend, runtime state owner, persistence format or backend permission changes are introduced.
