# 待办整理不再重置收尾催促

## 问题与修改

模型收到收尾催促后，单纯更新 `todo` / `todowrite` 清单也被当成新的工具工作，因而可以再次收到催促。在真实设计讨论中观察到模型继续扩写方案、更新清单、再次被催促的循环。

`crates/atomcode-coding/src/todo.rs::completion_nudge_allowed` 现在要求自上次催促后出现至少一个非待办工具调用，才允许再次提醒。使用既有 `is_todo_call` 同时识别当前和历史工具名；更新单项或重写完整清单均不重置提醒资格。

第一次提醒、最多三次的上限、问题结尾豁免、实际工具工作后的提醒均保持。未修改公共协议、持久化、技能、persona 或摘要模板，也没有新增生命周期所有者或 hook。仅做清单整理后停步的模型会少一次督促，这是本次策略收窄的范围。

## 验证

- 回归测试在旧实现上确实失败；混合实际工具工作的对照原本通过。
- todo 单测 48/48 通过。
- `cargo nextest run -p atomcode-coding`：1,177 项通过、9 项跳过。
- 随后新增的运行时集成回归连同原任务转向、等待、取消、provider error 测试：`cargo nextest run -p atomcode-coding --test task_steering`，5/5 通过。确认回合只有一个终态，待确认工作仍为 pending，不被假完成或清空。
- `bash gates/compile.sh`、`cargo fmt --all -- --check`、`git diff --check` 通过。
