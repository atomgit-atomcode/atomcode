# Browser origin enforcement backend plan

Baseline release/v5.2.7 923521f91, clean main and isolated worktree. Local Codex 806d9732c9 defines per-origin access/download/upload/full-CDP vocabulary in codex-rs/config/src/browser_use.rs; it does not supply a reusable browser execution backend here. Installed @playwright/mcp 0.0.85 and playwright-core 1.66.0-alpha-2026-11-09 explicitly describe allowed-origins as a convenience filter which does not cover redirects. Source coreBundle.js _setupRequestInterception confirms route.continue-based allow-listing. Do not expose those flags as the required enforcement boundary.

Build an optional source-only backend under integrations/browser-origin-scope, using the exact locally installed external MCP/Playwright dependencies and an independently owned temporary browser context. A loopback forward proxy validates every HTTP request and HTTPS CONNECT destination against trusted exact HTTP(S) origins, covering redirect requests, frames and subresources independently of MCP argument checks. Launch via Playwright pipe, force proxy handling of loopback, disable QUIC/non-proxied WebRTC, block service workers. No existing profile, extension, external CDP endpoint or backend environment override is imported. The proxy and browser share one optional-backend process lifecycle, separate from CodingRuntime ownership.

A transport gate restricts the backend itself to the established 16 browser tools and filters discovery; excluded evaluate/code/upload/CDP tools must fail before dispatch even for direct calls. Navigation accepts only allowed HTTP(S) origins. Stdio capability atomcode/browser-origin-scope v1 is advertised only by this backend. Trusted bounded policy is outside model arguments; malformed/absent policy refuses startup. Transfers default to no accepted download artifacts, no local-file uploads, and no full CDP. This foundation does not yet implement Codex's complete per-origin transfer/CDP policy matrix; those permissions must not silently accept unsupported allow settings.

Implement focused policy/proxy tests plus actual Chrome tests with controlled allowed/denied HTTP fixtures. Prove allowed requests work while direct, redirected, iframe, subresource, fetch/form and WebSocket attempts never reach the denied fixture; test CONNECT separately, file-upload/code/CDP refusal, download persistence refusal and bounded cleanup. Record versions and observed counters. No bundled browsers, Node or Rust dependencies; no network search or user profile use. Managed CLI integration and actual full per-origin policy matrix remain follow-up work, not completion claims.

Review security and actual execution limits explicitly: not an OS sandbox against shell or malicious same-user processes, not policy for effects performed by an allowed remote server, not proof about arbitrary browser protocols/egress. Keep HTTPS download-body inspection distinct from refusing persisted download artifacts. Run tests against real execution, not only proxy helpers or tool names.

## Prototype delivery evidence

Implemented the optional Node backend, trusted bounded exact-origin policy, protocol-aware loopback proxy, 16-tool execution/discovery gate, generated-artifact path restriction, isolated context ownership, bounded shutdown and source-only documentation. Neither stock `/browser` setup nor Rust runtime lifecycle ownership changed. Explicit artifact roots must be empty or carry the recognized ownership marker, cannot be leaf symlinks or filesystem roots, and keep the eviction-managed `files` directory separate from the marker.

Final validation:

- 12 standard-library Node tests passed: strict policy parsing, unsupported permission rejection, tool/argument refusals, discovery, opposite-direction RPC IDs, HTTP targets, CONNECT targets and scheme distinction, failed-launch proxy cleanup, serialized replacement, permanent-close fencing, close-error terminals, notification refusal, artifact ownership/symlink protection.
- Actual Chrome verifier passed seven groups on macOS 14.5 Apple Silicon, Chrome 157.0.8103.39, Node 22.22.0 and the pinned external runtime. Allowed HTTP/HTTPS/WS/WSS worked. Forbidden fixture recorded **zero TCP connections and zero HTTP requests**, including direct/redirect/frame/subresource/fetch/form/popup/WebSocket attempts. HTTPS attachment/blob downloads could not be saved. File-link denial was observed. Actual MCP capability/discovery and raw direct-call gates, image output, metadata/no-launch behavior, ignoring inherited attachment overrides, explicit close/reopen, EOF and SIGTERM cleanup of observed descendants passed; backend stderr was zero bytes.
- Evidence: `/tmp/atomcode-browser-origin-final-report.json` and accompanying `.png`; fixture PNG inspected with the expected ALLOWED_ORIGIN_FIXTURE marker. The report includes measured SHA256 for selected external dependency files (not whole-package attestation). Unit/live logs use `/tmp/atomcode-browser-origin-final-{unit,live}.log`.
- Actual production Rust registry/adapter opt-in test passed: local allowed navigation/snapshot/native image, redirect refusal without a forbidden connection, risky tool classification, capability version mismatch withdrawing tools, and stale adapter failure. This is explicit test-harness execution below the runtime/model loop, with no stored approval grant; it does not prove runtime approval E2E. Log `/tmp/atomcode-browser-origin-final-registry.log`.
- CLI crate regression: 669 passed, 6 opt-in tests skipped; the new origin test was also run explicitly and passed as recorded above.
- Full compile gate passed after adding the ignored Rust consumer test, including feature-gated targets and both negative controls. No production Rust/dependency/lock changes. Formatting and diff checks passed; Cargo.lock normal H flag and zero forbidden packages.

The initial real test correctly exposed a fail-closed plain-WebSocket incompatibility: Chromium uses CONNECT for ws:// as well as TLS. The corrected boundary parses plain WebSocket requests and checks authority while requiring a TLS prefix for HTTPS-only tunnels. Cross-scheme negative tests prevent converting one scheme's permission into a blind tunnel for the other. The Service Worker test originally expected rejection, while this pinned Playwright implementation deliberately resolves registration to undefined; actual verification now also requires zero workers and no worker-script fetch. Refused HTTPS navigation probes use separate owned pages so a late Chrome error document cannot race the next fixture case. No action retry/replay was added.

## Remaining scope

This is verified optional execution infrastructure, not completed Browser Use delivery. Managed CLI/TUI origin configuration, richer per-origin upload/download/CDP permissions, full CodingRuntime/real-model cancellation and unknown-result acceptance for this backend, and target Windows/Linux execution remain unaccepted. HTTPS download response bodies are opaque to the proxy; refusing accepted artifacts is not a claim that no bytes enter Chrome. No OS sandbox, arbitrary-protocol firewall, detached-descendant guarantee or signed backend attestation is claimed. Native GUI, other platform and final package-size requirements remain in the overall audit.
