# ACP in-flight cancellation and disconnect acceptance

Baseline release/v5.2.7 2a54b369f, clean main and isolated worktree. Reviewed ACP v1/v2 prompt tasks, serve_over connection lifetime, shared SessionState and stop_and_wait, CodingRuntime ownership and recent Git history. All browser effects are against isolated controlled local fixtures, using configured real model and scoped external Chrome backend; credentials stay in child environment.

Both v1 and v2 actual in-flight cancel cases commit once then hold the response. Native cancellation finishes before release, late HTTP response leaves the completed log unchanged, explicit session close/resume replaces the runtime, and a new turn reads /record once, takes one image and closes. Each submission count stays one. First harness diagnostics wrongly included the still-live ACP process in the post-session-close browser check; preserved separately. Fresh independent corrected fixtures distinguish the agent from owned browser descendants and pass. This is not replay of an unknown-effect operation in a previous fixture/session.

Actual stdin EOF cases in both protocols expose a production gap: the process and captured browser tree exit, but the in-flight native log has no TurnEnd or cancellation tool result. The diagnostic reporter itself indexed a missing terminal and failed; absence is independently verified from the native log. Another earlier v1 harness only accepted browser_type, refused the supported browser_fill_form and disconnected before any submit; preserve as a harness diagnostic, not EOF-effect evidence.

Keep one reference to the shared Sessions table in serve_over until the protocol router ends. Drain it and concurrently await the existing bounded stop_and_wait for each session, regardless of success or transport error, before returning the original connection result. This retains CodingRuntime as sole owner, uses existing Cancel/Shutdown paths and persistence facts, and avoids a second state machine or protocol/schema change. Concurrent existing stops bound teardown across multiple sessions instead of accumulating a timeout per session. Do not make browser operations replayable or add automatic reconnect.

Add a deterministic actual v2 duplex/runtime regression with a provider stream that emits an observed chunk and then remains pending. End the client connection after the chunk without cancelling/closing its session; require serve_over to return only after a native Cancelled terminal and released lease. Add concurrent bounded cleanup coverage, then rerun affected CLI tests, real stdio EOF browser cases, compile/format/layer/product-dir/lock checks. This does not prove arbitrary detached process containment, other desktop platforms or all remote frontend semantics.
