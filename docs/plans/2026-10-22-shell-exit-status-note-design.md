# Shell 结果的退出状态提醒

基线：release/v5.2.5，586a84404；保留本轮尚未提交的工具主说明改动。
此前主说明复验显示采用改善，但真实构建仍混用输出管道与 echo 收尾。

用户已确认增加结果提醒。仅对可识别的构建、测试、安装前端接 head/tail/tee，
或无条件以 echo/printf 收尾的常见包装给出提示；使用现有 Bash 语法树，
不以输出里的 error 字样猜测失败，不把引号、注释或 here-doc 文本当命令。
普通 cat/grep 查询管道不提醒；正确显式返回原状态的常见写法不提醒。
这是有限的语法启发，不是 shell 成功证明或所有包装的检测器。

提醒说明当前状态属于整条命令，不能独自证明原构建/测试成功；若已有明确状态
传递证据应据此判断。artifact 能力可用时给出 output_tail_lines/fetch_output 替代，
不可用时只解释状态含义。不得要求仅为补状态而重新执行已经执行的工作。
命令原样执行，不拦截、不改写、不自动重试、不修改 ToolResult.is_error 或退出状态。

前台在执行结果预览后追加；后台沿用现有 Job owner 携带一份待投递诊断，
首次 poll 返回时取出，避免每次等待反复提醒。该字段只属内存结果展示，
不进入公共协议/会话格式，不复制 command 到诊断、不引入新的 job 生命周期。
提醒放在预览外，避免被按行裁剪或与真实进程输出混算。

验证范围：阳性/阴性语法矩阵（含 quoted 文本、实际数据管道、&& 成功链、
显式保留状态、嵌套 shell）、前台真实管道退出码不变且只执行一次、后台
提醒只投递一次且游标和终态保持；artifact 开关下不广告不可用参数。
完成受影响 crate 回归、编译门、格式检查。模型验证与机制验证分开报告。

## 实现与边界

检测器放在 capabilities 的 bash/exit_diagnostic.rs，复用 parse_bash。前台只在已完成且整条命令状态为 0 时追加提醒；后台 Job 保存一份 pending 标记，首次 poll 消费，running/0 时展示，已知非零或 killed 不增加此提醒。非法 poll 参数或取消等待不会消费诊断；提醒在原生预览完成之后追加，实际捕获 artifact 不混入该说明。

只识别常见标准前端（如 cargo test、python -m pytest/pip、python setup.py build_ext、make、npm install 等），不推断任意脚本、动态命令名或 shell -c 字符串内部行为。管道过滤和无条件打印收尾是语法启发；&& 成功链、直接同作用域 set -o pipefail（支持随后 +o 关闭）及常见显式返回状态路径有阴性判据。函数定义体不当作已执行工作。复杂状态传播未被证明；有意过滤的构建前端查询也可能得到提醒，它不代表检测到真实失败。

可选诊断对 64KiB 以上、遍历深度 64 以上等输入不作穷尽分析；不会拒绝原命令。没有新增依赖、公共协议、持久化字段或进程 owner；没有改变风险分类和审批。

## 验证结果

Capabilities 最终 1133/1133、Harness 271/271、Coding 1168 通过（9 跳过）；gates/compile.sh、fmt、diff 检查通过，Cargo.lock 未变，无私有依赖污染。新增真实进程回归证明原命令只执行一次、包装返回 0 不被改写、正确保留原状态时仍返回 23；后台虚拟时钟回归证明诊断只投递一次、参数错误不消费、游标/回收/终态不变，artifact 开关保持诚实。

同模型两个固定小探针均按原命令执行一次、脚本未改、提醒各出现一次：管道场景没有误报构建成功，后台以打印的 EXIT:23 识别失败并区分包装状态 0。没有重复执行。后台回答另有未经核验的编译器原因猜测，不作为本轮状态判据。没有无提醒配对对照，因此不宣称因果效果或总体遵循率；未重跑 SWE-bench 题目或 Windows 实机。
