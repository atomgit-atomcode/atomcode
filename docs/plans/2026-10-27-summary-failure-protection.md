# 摘要失败与异常流终态保护

## 问题与责任边界

手动/自动压缩在配置了摘要 provider 但调用失败时，仍会提交历史裁剪。harness 会补一份请求清单，但该清单仅保留用户请求片段、工具名与已有摘要，不能代替助手此前给出的设计结论。收到半截摘要后报错、达到输出上限、缺少完成事件，或超过本地字节上限时，也不能授权替换完整历史。

继续使用 CodingRuntime 装配的 OverflowCompaction，以及 harness 将策略投影为原生会话事实的既有路径。不新增生命周期 owner、hook、协议或持久化格式；原始磁盘事件不被删除，修改的是后续模型可见的上下文投影。

## 最终行为

- 已配置摘要模型但调用失败、输出为空或不完整：手动/自动压缩退回现有工具输出精简，不裁用户和助手对话；没有可精简内容则不修改。
- 摘要必须非空、收到正常完成事件、没有长度截断，且完整内容在64KiB限制内。超限时拒绝整份摘要，不提交截取的前缀。
- 显式无摘要 provider 的原有降级，以及真正上下文溢出的应急恢复策略保留。这些应急路径仍可能损失细节。
- OpenAI 兼容流的 EOF 先处理最后一条未带换行的记录；没有终态的部分输出返回中断错误，不冲刷工具调用。收到合法结束原因但缺 `[DONE]`、明确 `[DONE]`、空响应与非 SSE 错误诊断保持兼容。
- 内容过滤与未知结束原因返回错误；工具片段保护上限逐片段检查，不能靠单个大数组绕过；长度截断不执行缓存的工具调用。发出错误后停止读取上游，不隐藏重放。
- 异常终态前已收到的 usage 先交付一次，再返回错误；没有上游数据时不虚构用量。

未知或非标准结束码现在会明确失败，需要按网关协议适配，不能继续默认按成功处理。正常摘要仍依赖模型保留事实；本修复不能保证所有设计发散和事实漂移都消失。

## 验证

- capabilities 默认 feature 单元测试1096项通过；HTTP/压缩集成17项通过。
- harness 的 compaction_strategy 集成7项通过。新增原生会话投影回归覆盖403、部分输出后报错及手动/自动压缩；确认实际调用了摘要模型、没有提交 Compacted、助手已确认的字段定义仍可见，且工具调用与结果不孤立。
- 新增解码器回归覆盖无终态 EOF、末行无换行、内容过滤、未知结束码、工具片段上限、长度截断和错误前的 usage 交付。
- 全仓及 feature 编译门、格式和 diff 检查通过。

没有将用户原始日志、会话内容、真实模型响应或未验证的提示词候选加入发布提交。实现回归通过不等同于已经证明用户原案得到全面解决。
