# Grape one-step authorization and native tools

**Goal:** `atomcode grape connect --server <url>` opens Grape's consent page, obtains a dedicated revocable credential without copying keys, and makes native Grape tools usable in subsequent CLI/TUI/WebUI requests.
**Architecture:** Grape owns authentication, grants and remote jobs. AtomCode auth owns the local private credential; capabilities owns typed HTTP tools; coding mounts them. No kernel changes or second agent/session owner. The official cloud is the default, and private deployments select the URL explicitly; an AtomGit bearer token is never sent to it.
**Tech Stack:** Python/FastAPI and the existing Grape database/auth; Rust reqwest/serde and existing secure credential writer; mocked protocol tests and local cross-process HTTP verification.

Baselines: AtomCode c042a8226 (dirty main.rs/headless_json.rs kept separate), Grape 5014f1f7e (untracked .atomcode kept separate). Worktrees /tmp/atomcode-grape-one-click and /tmp/grape-atomcode-device-auth.

1. Implement RFC-8628-style device authorization with explicit client ID, public user code and secret device code. Hash codes in a shared DB table. Grant lifetime ten minutes, five-second polling with slow_down, browser-only explicit approval/denial, bounded start/approve attempts, atomic one-time issuance, current-account/token-version validation and no plaintext credential at rest on Grape.
2. Issue a dedicated API token with an enforceable AtomCode integration scope: repository/scene/knowledge/event/task-log reads, A2A handoff/status and self-revocation only. Preserve existing public API key behavior. Existing repository and organization checks remain authoritative. Consent describes the actual access; no automatic job dispatch at login.
3. Add a same-origin Grape consent page using the existing browser JWT and login flow. No access/device secret in browser URLs, no user-provided redirects and no automatic approve-on-GET. Expose revocation in the existing API-key management as well as client disconnect.
4. Add AtomCode's device protocol and per-service private credential store with origin-bound HTTPS (HTTP only literal loopback), no redirects, bounded responses/timeouts and sanitized failures. A canceled/denied/expired flow cannot overwrite the previous connection. Secret fields are never model-visible or Debug output.
5. Add native `grape_project`, `grape_task`, `grape_knowledge` tools, discovered on demand. Query actions safe; handoff risky, requires explicit existing Issue and stable idempotency key. Read paged/bounded logs, never ingest full history. Do not add arbitrary REST, deployment, API-key administration or automatic Issue creation. Remote work never silently includes local uncommitted changes.
6. Add connect/status/disconnect CLI entry and usage docs. The same stored connection serves all frontends; selecting a project or authenticating does not authorize automatic remote mutations.
7. Validate denial, expiry, polling/backoff, replay/concurrency, scopes, account disable/revocation, credential-origin and log secrecy, native tool payloads, and a local mock browser-to-client round trip. Run affected Python/Rust tests, compile gate, fmt and Cargo.lock checks. No real account login or remote task is performed, and neither repo is pushed/deployed without a further instruction.
