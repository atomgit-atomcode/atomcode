# /provider 管理交互重设计

日期：2026-11-20
范围：`crates/atomcode-tui`（面板状态机与渲染）
不涉及：配置文件格式、宿主写入端口（`Step` 的写操作全部复用）、发现层（`atomcode-capabilities` 的 discovery）、daemon / webui、kernel / runtime 生命周期。

## 1. 问题

`/provider` 与 `/model` 是同一块面板（`providers::Panel`，账号 / 模型两个页签 + drill）。管理流程别扭的具体原因：

1. **同一动作多处出现且两页签不一致**：编辑在账号页是底栏 `^e`，在模型页是行内 `[ 编辑 ]` 按钮；添加行尾巴标 `^a`，底栏也有 `^a`；底栏提示用强调色且可点击，看起来也是按钮。
2. **Ctrl 组合键过多**：列表 `^a ^n ^e ^d`，表单 `^s ^o ^f ^n`，同一个 `^n` 在列表和选择器里含义不同。
3. **两个添加键**：`^a`（发现）与 `^n`（手动），要求用户先理解区别。
4. **回车含义随行变化而编辑不走回车**：账号行 = 下钻，未配置账号 = 连接，模型行 = 切换，添加行 = 添加。
5. **底栏 9 项**，窄终端截断时最先丢掉 `esc`、`⇥`。
6. **表单键义随状态变化**：`⏎` 是继续 / 保存 / 连接并使用，`^s` 仅保存，`←→` 有时换值有时移光标；批量选择器是「空格勾选 + 回车提交 + ^s」的第三套语义。

## 2. 参考

| | 管理入口 | 要点 |
|---|---|---|
| opencode | `/connect` → 提供商 → 账号列表 | 「Add account」是列表第一行；回车 = 启用，`Ctrl+R` 改名，`Ctrl+D` 删除且按两次、确认文字替换行标题；底栏只列对当前行有效的动作 |
| oh-my-pi | `/models` 全屏 hub + `/login` `/logout` + `models.yml` | 模型来自目录 / 发现而非手填；未配置提供商在右侧直接写出解锁方式；单值修改用底部条带；底栏逐行变化；可完全用鼠标，但无行内按钮，底栏提示可点 |
| codex | 无 TUI 管理 | `/model` 底栏只有「⏎ 确认 · esc 返回」 |
| deepseek-harness（GUI） | 设置页提供商行 | 一次只展开一张编辑卡；模型在提供商卡内编辑；高级项收进折叠区 |

共同点：回车只做「这一行最常用的事」；添加是列表里的一行；删除行内确认；底栏 ≤ 4 项且随行变化；每个动作只出现一处。

## 3. 交互原则

1. **回车 = 用它**：对这一行做最常用的那件事（切换 / 打开 / 添加 / 编辑连接）。
2. **`Ctrl+E` = 改它**：编辑光标所在的东西，无论它是提供商还是模型。
3. **`Ctrl+D` = 删它**：唯一的删除方式，按两次，确认文字写在该行上。
4. **添加是一行**，不是快捷键。三处添加行（`＋ 添加提供商`、`＋ 手动添加模型…`、`＋ 添加模型…`）**固定在列表区底部、不随滚动消失**：逻辑上仍是最后一行（↓ 走到底或 `End` 直达），绘制在滚动窗口之外、底栏之上，列表再长也始终可见。
5. **底栏只列当前行可用的动作**，不可用的不显示，按了无反应不报错。窄屏时优先保留 ⏎ 主动作与 `esc`，其余按各画面规定的顺序从后往前省略（未单独规定的画面：越靠后的动作越先省略）。
6. **每个动作只出现一处**：去掉行内按钮；底栏提示保留可点击（点击 = 按该键），但用普通提示样式而非按钮样式。
7. 打字永远是筛选（沿用现有约定，见 `providers.rs` 模块文档）。
8. **组合键写作 `Ctrl+E`**，与产品其他提示文案一致；不再用 `^e` 这种 Unix 记法。

## 4. 结构

```
/model ──────────────► 模型列表（切换为主）
   │ ⏎ 切换  Ctrl+E 编辑  Ctrl+D 移除  F2 模型卡
   │ ＋ 添加模型… ──┐
                    ▼
/provider ─────────► 提供商列表 ──⏎──► 提供商详情
                     Ctrl+E 连接表单        连接行 / 已添加 / 服务端还有 / ＋ 手动添加模型…
                     Ctrl+D 删除            Ctrl+E 模型编辑界面
```

页签与 `⇥` 换页取消。面板只有三种画面：`Models`（/model）、`Providers`、`Detail { account }`，另有覆盖其上的表单。

### 4.1 /model：模型列表

切换行为**不变**：按账号分组、正在用的排最前、打字筛选、回车切换并在模型声明档位时接着选思考强度、`F2` 模型卡。

| 光标所在 | ⏎ | 其他 |
|---|---|---|
| 可编辑模型 | 切换 | `Ctrl+E` 编辑 · `Ctrl+D` 移除 |
| 托管模型 | 切换 | — |
| ＋ 添加模型… | 打开提供商列表，默认选中当前模型所在账号（无当前模型时选第一个可编辑账号）；`＋ 添加提供商` 照常可见。即使只配了一个账号也不直接进详情：用户这次可能想接第二家 | — |

底栏：`⏎ 切换 · Ctrl+E 编辑 · Ctrl+D 移除 · F2 模型卡 · esc 关闭`（托管行去掉 `Ctrl+E`、`Ctrl+D`）。宽度不够时按 `F2 模型卡` → `Ctrl+D` → `Ctrl+E` 的顺序省略，⏎ 主动作与 `esc` 始终保留。

去掉：行内 `[ 编辑 ]`、添加行上的 `Ctrl+A` 标记、`Ctrl+A`、`Ctrl+N`、`⇥`。

从 /model 打开的表单或提供商画面，`esc` 返回 /model，光标回到原模型（沿用 `follow_cursor` 按 id 对齐）。

### 4.3 提供商详情

```
 ‹ DeepSeek
 ▸ 连接   api.deepseek.com · ✓ 密钥
   ── 已添加 ──
   deepseek-v4-flash   1M · 输出 384K · 思考 high
   deepseek-v4-pro     1M
   ── 服务端还有 ──
   deepseek-chat       128K · 输出 8K
   deepseek-reasoner   128K · 输出 64K · 思考 low/medium/high
   ＋ 手动添加模型…
```

| 光标所在 | ⏎ | 其他 | 底栏 |
|---|---|---|---|
| 连接行 | 连接表单 | — | `⏎ 编辑 · esc 返回` |
| 已添加模型 | 切换（可接着选强度） | `Ctrl+E` 编辑 · `Ctrl+D` 移除 | `⏎ 切换 · Ctrl+E 编辑 · Ctrl+D 移除 · esc 返回` |
| 服务端还有的模型 | 添加 | `Ctrl+E` 编辑后添加 | `⏎ 添加 · Ctrl+E 编辑后添加 · esc 返回` |
| ＋ 手动添加模型… | 打开模型编辑界面（ID 为空） | — | `⏎ 手动添加 · esc 返回` |

**发现**：进入可编辑提供商的详情即发起 `Step::Discover { account }`。结果按账号缓存在面板上，直到面板关闭。每个账号带一个代数（generation，见下文「账号代数」）：**连接保存成功**（端点、协议或 Key 变了，账号 id 不变而可用模型可能全变）时，代数加一，清空该账号的缓存，作废在途请求，并重新发起发现；**账号删除成功**时，代数加一，清空缓存，作废在途请求，回到提供商列表，不再发现。返回的结果按账号 id + 代数 + 请求序号（现有 `next_discovery_id`）核对，不匹配的丢弃。
- 加载中：「服务端还有」段显示「正在获取服务端模型…」。
- 失败：显示现有的诊断文案（含 Ollama 连接提示），「＋ 手动添加模型…」照常可用。
- 「服务端还有」 = 发现结果减去已配置（按线上模型名，沿用现有去重）。
- 结果来自目录候选时（端点列不出模型），段标题换成 `ProviderCatalogCandidates`「models.dev 目录候选 · 账号可用性未验证」。

**筛选时的手动添加**：输入筛选词且服务端列表没有完全匹配时，固定行显示为 `＋ 手动添加「<筛选词>」`，⏎ 打开模型编辑界面并预填该 ID。

**添加**：⏎ 发起写入（`Step::SaveModels` 单条草稿，字段用发现结果预填）。不做多选模式。宿主的保存可能先异步补元数据（`plugin.rs` 的 `enrich_models` → `Wake::ProviderModelsEnriched`）再写配置，所以面板要有「保存中」状态：
- 面板按（账号, 模型 ID）记录在途的添加，该行显示「添加中…」；对同一行的再次 ⏎ 忽略，不重复提交（写入端会拒绝重复模型，否则用户会看到一次成功一次报错）。
- 光标在按下 ⏎ 时就前移到下一个候选，因此可以连续快速添加多个；在途的行留在原位。
- **写入前核对账号代数**：草稿发起时记下账号代数，补完元数据、真正写入前再核对一次。代数变了（这期间连接被保存或账号被删除）就**丢弃整个请求，不写配置**，该行清掉「添加中…」，提示「连接已变更，未添加」。只是关闭面板、切换画面或移动光标，不算变化，已确认的保存照常完成。不能只靠写入层兜底：`provider_book::add_models` 遇到账号不存在时会按预设新建账号（`provider_book.rs`），旧请求会让刚删掉的账号重新出现，或者把旧端点的模型加到新连接上。
- 写入**成功后**该行才移入「已添加」；失败则保留在「服务端还有」，清掉「添加中…」并显示错误，可再按 ⏎ 重试。
- 最后一个候选也被添加后，光标落在固定行 `＋ 手动添加模型…`，绝不落到「已添加」的行上，避免下一次 ⏎ 意外切换模型。

**无可用模型时自动启用**：只在宿主已明确判定「当前没有可用模型」时，添加的模型写入后顺带 `Step::Use`，取代现有「连接并使用」。判据用宿主给的信号，不用 TUI 的推断：首次配置（`moment.model_setup_required`）或就绪探测报告不可用（`moment.unready`，如退出登录后原模型失效）。**不用 `ProvidersView::live_row()`**：它在两个账号用同一线上模型名、会话刚启动尚未报告模型、当前模型已从配置移除时都返回 `None`（`providers.rs` 的 `marked_row`），而这些会话可能仍能正常对话。普通管理入口一律只保存不切换，想用就在该行按 ⏎。

**自动启用资格只给一个请求**：资格在**按下 ⏎ 的那一刻**判定并占用，不在写入完成时判定，与异步返回的先后无关。
- 资格由**宿主侧**（TUI 插件）按会话保存：`auto_use_claim: Option<请求序号>`，不放在 `Panel` 上。面板可以关了再开，而在途的请求仍要能被核对。面板从 `Moment` 读「资格是否空闲」来决定底栏文字。
- 处于恢复状态且资格空闲时，「服务端还有」行的底栏写 `⏎ 添加并使用`，按下即以本次请求序号占用资格，草稿带 `use_now: true`。
- **资格被占用期间，所有候选行（包括重开面板后）的底栏都只写 `⏎ 添加`**，只保存不切换。不存在「撤销旧资格、再给新请求」的操作。
- **撤销资格的唯一方式是显式切换**：面板里对已添加模型按 ⏎ 切换（含选思考强度），或输入 `/model <id>`。被撤销的请求仍然完成**保存**，但不再切换。
- **完成时的核对，分三件事**：
  - 能否**保存**：只看账号代数（见下文「账号代数」），代数变了就整体丢弃。
  - 能否**启用**：会话未变，**并且** `auto_use_claim` 仍等于本请求序号，两者都满足才切换，切换后清空资格。
  - **失败**（保存失败或切换失败）时只释放**自己的**资格：`auto_use_claim` 等于本请求序号才清空，否则不动。

**「添加并使用」等待切换的真实结果**：现有 `Step::Use` 把 `/model …` 当作一行输入放进队列（`Wake::Chose`）后就立即关闭面板（`plugin.rs`），真正的 `SwitchModel` 成功、拒绝或 `DoneWithNote` 要稍后在 `commands.rs` 里才返回，面板收不到。所以「添加并使用」不走这条即发即关的路径：
- 保存成功后执行切换，等待结果后带上请求序号以 `Wake` 回送给插件。等待期间面板保留，A 行显示「切换中…」。
- **结果要分开记录模型切换和强度设置**。现有 `/model <id> <effort>` 分两步：先 `SwitchModel`，再走 `/effort`；`/effort` 被拒时整条命令返回 `Outcome::Refused`，而此时模型已经切到 A（`commands.rs`）。所以不能只看一条命令的 `Said` / `Refused`。实现上插件依次派发 `/model <id>` 与 `/effort <level>` 两条命令（`plugin.rs::switch_and_set_level`；`level` 取草稿的强度，否则 `default`，与原「连接并使用」一致），各自的 `Outcome` 记进 `SwitchResult { model: Result<String, String>, effort: Option<Result<String, String>> }`，成功文本里原样带着宿主的 `DoneWithNote` 提示。命令实现仍然只有一份，`commands.rs` 不改；`/model` 返回 `Do(PickEffort)` 也算切换成功，其中的 `note` 保留。
  - `model` 成功、`effort` 失败：A 标为当前模型，提示「已切换到 A，推理强度设置失败：<原因>」，按切换成功处理，用户不需要再切一次。
  - `model` 或 `effort` 成功且带 `note`（`DoneWithNote`）：提示原样显示，两步都有时都显示。
  - `model` 失败：按「切换被拒」处理。
- **回执能不能动面板，成功和失败用同一条规则**：每次打开面板都分配一个实例序号；发起请求时记下（面板实例, 请求序号），面板上记 `awaiting_switch: Option<请求序号>`。只有当前面板就是发起时那个实例、仍停在同一账号的详情页、并且 `awaiting_switch` 等于本请求序号时，回执才能关闭面板（成功）或把光标移到 A 行（被拒）。其他情况一律只显示结果提示，不碰当前的面板、表单、光标和草稿。
- 「切换中…」期间按 `esc` 可以离开，离开就清掉 `awaiting_switch`，之后回执只显示提示。
- 面板里普通的 ⏎ 切换（包括切换失败后在 A 行上重试）仍走现有的即发即关路径，结果显示在对话区。

**自动启用的三种结果**（沿用现有「先保存、再切换」的顺序，`plugin.rs` 的 `apply_provider_step`）：

| 结果 | 界面 | 资格 | 再按 ⏎ |
|---|---|---|---|
| 保存失败 | 该行留在「服务端还有」，显示错误 | 释放（仅当属于自己） | 重试添加；仍处于恢复状态、资格空闲时再次占用资格 |
| 保存成功、切换被拒 | 该行在「已添加」里，显示「已添加，切换失败：<原因>」；回执规则允许时光标停在这一行 | 释放（仅当属于自己） | 这是已添加的行，⏎ 就是切换，只发一次 `/model`，不会重复添加 |
| 切换成功、默认模型写盘失败 | 照原样显示宿主的提示（`DoneWithNote` / `ModelNotKept`），告诉用户本次在用 A，但重启后不保留；按上面的回执规则决定是否关闭面板 | 已消耗 | 不需要 |
| 切换成功、强度设置失败 | A 为当前模型，提示「已切换到 A，推理强度设置失败：<原因>」；按上面的回执规则决定是否关闭面板 | 已消耗 | 不需要再切模型；要调强度用 `/effort` |

「保存成功、切换被拒」时光标停在 A 行，是「最后一个候选添加后光标不落到已添加的行」的唯一例外：恢复状态下，用户要的正是切换过去。

**账号代数**：放在 TUI 插件（宿主侧）而不是 `Panel` 上，因为面板关闭后在途的请求仍需要核对。连接保存成功、账号删除成功时加一。发现结果和添加请求共用这一个代数。现有 `Wake::ProviderModelsEnriched` 用「面板与发起时完全相等」（`still_here`）来决定是否保留 `use_now`。新设计里光标移动、在途标记都会改变面板，这个判据会误判，因此改为：账号代数决定能否保存（变了就整体丢弃）；能否启用另看会话与请求序号，见上文「完成时的核对」。

**托管提供商详情**：只读。连接行换成登录状态与「/login 重新登录 · /logout 退出」说明；模型行只有 ⏎ 切换；无「服务端还有」与「＋ 手动添加模型…」。

### 4.4 连接表单

字段：名称（仅新建）、协议（`←→` 选择）、端点、Key（协议需要时）。预设的精简流程沿用 `AccountForm::fields` 的非 advanced 分支；其余字段收进表单末尾一行「更多设置 ▸」（⏎ 展开），取代 `Ctrl+O`。

固定键义：`↑↓`/`⇥` 换字段 · `←→` 在选择型字段上换值、在文本字段上移光标 · `⏎` 保存（「更多设置 ▸」行上是展开）· `esc` 放弃。

保存新提供商后进入它的详情页，复用 `SaveAccount.listed` 带回的发现结果，直接落在「服务端还有」第一行。Ollama 的发现改为保存后自动进行，取代 `Ctrl+F`。

密钥约束不变：表单只记已输入字符数，字符本身只在宿主的 `String` 里，经 `leave_form` 在任何离开路径上清除。

### 4.5 模型编辑界面

三个入口共用一个界面，只是预填不同：

| 入口 | 预填 | 保存后 |
|---|---|---|
| 已添加模型 `Ctrl+E`（详情页或 /model） | 当前配置 | 更新该模型 |
| 服务端还有的模型 `Ctrl+E` | 发现结果 | 加入「已添加」 |
| ＋ 手动添加模型… `⏎` | 仅空的模型 ID | 加入「已添加」 |

字段：模型 ID（仅手动输入时可改）、上下文窗口、最大输出、识图（自动 / 是 / 否）、思考档位、默认强度。账号字段去掉（由所在详情页决定），Key 字段去掉（属于连接表单），「设为默认模型」字段（`ModelField::Default` / `ModelDraft.default`）去掉，理由见下。

**`default_model` 何时改写**：只在会话切换模型时改写。宿主的 `SwitchModel` 本来就会持久化切换结果（`atomcode-cli/src/host.rs` 的 `set_default_model`，防止重启后回到旧模型），所以「本次使用」和「以后默认」在 TUI 里已经是同一件事，表单里的「设为默认」是第二个入口。

| 操作 | 当前会话 | `default_model` |
|---|---|---|
| ⏎ 切换（/model 或详情页） | 切换 | 由 `SwitchModel` 持久化（现状） |
| 普通添加（⏎ 或 `Ctrl+E` 保存） | 不变 | 不改（`default: false`、`use_now: false`） |
| 编辑已添加模型 | 不变 | 不改 |
| 无可用模型时自动启用 | 切换 | 经同一个 `Step::Use` → `SwitchModel` 持久化；草稿本身 `default: false`，不走第二条写入路径 |

顺带消除一个现存的隐患：现在编辑表单的 `default` 预填自 `row.current`（会话标记，`providers.rs` 的 `ModelForm::edit`），编辑当前模型并保存会顺手改写 `default_model`。去掉该字段后，这条路径不再存在。

固定键义：`↑↓`/`⇥` 换字段 · `←→` 换预设值 · 数字键输入自定义值 · 在档位字段上 `空格` 开关该档 · `⏎` 保存 · `esc` 放弃。去掉 `Ctrl+S`、`Ctrl+O`、`Ctrl+F`、`Ctrl+N`。

> 采用编辑表单而非 oh-my-pi 式的底栏条带（一次只改一个值、立即保存）：「编辑后添加」要求全部字段一次提交、`esc` 什么都不发生，条带做不到。原表单的问题在于键义随状态变化，不在于它是表单；固定键义后即可解决。

### 4.6 能力显示

模型行显示：上下文 · 输出 · 识图 · 思考档位。拿不到的项不写；一项都没有时写 `ProviderNotProvided`「未提供」。窄终端按 思考 → 识图 → 输出 的顺序省略，上下文保留。「已添加」行显示当前配置值，不是服务端原始值。

取数链路（现状，`discovery.rs::discover`）：
1. 端点模型列表接口；字段齐全则止步。
2. 有缺失或端点列不出时查目录：
   a. `models.opencode.ai` 按端点匹配提供商：套餐相关的上下文、输出、识图、档位、默认档位；端点被多个提供商共用时不补。
   b. `models.dev/models.json` 按模型名：只补仍缺的上下文、输出、识图。
3. `merge_listing`：端点值优先，目录只补空缺。

面板不区分值的来源：端点给的与目录补的同样显示、同样预填。数值不准时用户 `Ctrl+E` 修改即可。唯一保留的来源提示是整段级别的：端点列不出模型、列表全部来自目录候选时，段标题如 4.3 所述换成「models.dev 目录候选 · 账号可用性未验证」（现有行为），因为它说的是「这个账号能不能用这些模型」，不是数值的来源。

### 4.7 鼠标

- 单击一行 = 选中；再点一次或双击 = ⏎。
- 点底栏某项 = 按该键（保留 `legend_buttons` 的绘制与命中同源）。
- 滚轮滚动列表。
- 不加行内按钮。鼠标捕获可用 Ctrl+G 关闭，键盘必须能完成全部操作。

## 9. 风险与回归点

- **首次运行与 setup 入口**：`model_setup.rs`、`plugin.rs` 中打开提供商面板的路径（近期 dff20b139）改指提供商列表或对应详情页；`atomcode-cli/tests/tui_front.rs` 回归。
- **视图刷新后的光标**：保存 / 删除 / 切换后 `ProvidersView` 重建，光标按 id 对齐（`follow_cursor` 扩展到 `Configured` / `Available`）；添加后光标停在下一个可添加行。
- **迟到的发现结果**：离开、重进详情页，或保存连接、删除账号之后，旧请求的结果不得写入新状态（代数核对）。
- **在途添加**：异步补元数据期间面板可能被关闭、切画面或刷新；结果回来时按（账号, 模型 ID）找回对应行，找不到就只刷新视图。写入前核对账号代数，变化即丢弃，不写配置。
- **自动启用的竞态**：资格在按下时占用、存于宿主、完成时核对；之后的显式切换会撤销它。关闭再打开面板不会让旧请求重新拿到资格，也不会给新请求第二份资格。
- **切换结果回送**：「添加并使用」要等切换的结构化结果（`SwitchResult`），需要新增一条带请求序号的 `Wake`，并把 `/model` 分支的主体抽成共用函数；`/model` 命令的文案和行为必须保持不变（现有命令测试回归）。只用于这一条路径，普通切换不变。
- **密钥**：所有离开表单的路径经 `leave_form` 清空。新增的「保存后进入详情」路径也要覆盖。
- **托管行**：只读规则覆盖 /model、列表、详情三处，`Ctrl+E` / `Ctrl+D` 静默无效。
- **固定添加行与滚动窗口**：`window()` 计算的可用行数要扣掉固定行；光标落在固定行时滚动窗口停在列表末尾；鼠标命中区与绘制位置同源。
- **i18n**：中英两份同步，删除的条目确认无其他引用。
