## Delivered projection and tests

Both protocol generations now render each result as its original text followed by ordered standard ACP image content blocks. Data and MIME are copied without inventing filenames, and error status remains failed. Live and historical wire mappings reuse the same content builder for each protocol. Approval subjects and their preceding pending tool records include the actual native arguments as rawInput; the three native permission options and RPC/request correlation are unchanged.

Replay reads the strict native aggregate and its committed events after runtime resume. It uses kernel provenance to locate images on the exact visible ToolResultLogged fact and FIFO-pairs duplicate call IDs, while human text uses derive_messages_with_meta to avoid model-only retained-input framing. Rewound/compacted images do not reappear, synthetic model image carriers do not become extra user pictures, and no new event schema, writer or kernel hook is introduced. Existing old-native fixture conversion is performed by SessionManager::open_as_events, matching the production resume owner. Three old unit fixtures encoded tool results as User messages; they now use the existing native Message::tool_result constructor rather than restoring a driver compatibility fallback.

The two new live image regressions failed before the correction (one text block instead of text plus two images). Final targeted ACP tests: 94 passed, covering both live wire shapes, replay equality, ordered/error images, duplicate IDs, rewind/compaction and existing snapshot/presentation conversion. Full affected CLI crate: 685 passed, 13 opt-in tests skipped. Existing v2 full permission round-trip coverage now independently asserts the exact structured command arguments in the request subject. No Rust dependency or Cargo.lock change was needed.
