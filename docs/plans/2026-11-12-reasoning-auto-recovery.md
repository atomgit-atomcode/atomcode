# Opt-in bounded reasoning recovery

Baseline: release/v5.2.7 f7636549d, clean. Reviewed stream recovery, request timeout, partial reply checkpoints, effort selection, per-session progress ownership, coding mount/config, and existing reasoning-deadline tests/history. Existing recovery row owns the attempt; no second controller/hook or provider lifecycle is introduced.

Enable via ATOMCODE_REASONING_RECOVERY_TIMEOUT_SECS (1..3600); unset/0 keeps existing manual behavior. First reasoning-only local timeout may temporarily lower one supported effort level, at most once per live turn. Recovery has an absolute wall-clock limit including prefill. Preserve original reasoning and tool history; never recover incomplete tools. On recovery failure stop automatic work with a local non-retryable error rather than feeding provider retry layers. Cancellation stays agent-owned. Restore effort after success/failure; never change session/model defaults.

Use existing per-session recovery progress for the one-use gate. During the bounded recovery only, flush the existing incremental reply checkpoint buffer on drop so timeout/cancellation preserves the final partial chunk. Existing event format/persistence writer remain authoritative. Tests cover default-off, success/effort restoration, total deadline, partial preservation, cancellation, unsupported lower effort, unsafe tools, session/turn isolation, and coding mount wiring. Run affected harness/coding tests, compile and format/lock gates.

## Final behavior and validation

- Default off. Example: `ATOMCODE_REASONING_RECOVERY_TIMEOUT_SECS=60 ./target/release/atomcode`. A positive setting bounds the one lower-effort recovery, including its prefill and streaming; the original request retains its separate prefill/continuous-reasoning budgets. Unsupported lower effort and incomplete tools do not authorize automatic work. A further error or truncated response stops with the existing Timeout terminal and a local non-retryable recovery-exhausted code.
- The existing Progress owner keeps the one-use gate per live session/turn; steer does not replenish it. Confirmed tool-result protection is carried into recovery. Effort changes are request-local; normal defaults and the following turn are unchanged. Existing incremental reply checkpoints preserve final partial text when the recovery future is dropped.
