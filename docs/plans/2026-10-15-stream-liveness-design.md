# 长流式响应的活性预算

基线：release/v5.2.4，c6df1173a；保留工作区中其他 TUI 修改。

根因：llm-request-timeout 默认 600 秒，外层取消会丢弃仍在持续输出的 provider 流，绕过携带 partial 的空闲错误路径。

设计：该行保留，但默认 request_secs=0 表示禁用整请求上限，正整数仍提供显式整请求预算。coding 配置将默认内容空闲预算从 120 秒调为 300 秒；首内容预算保持 600 秒，环境变量覆盖保持不变。所有 coding driver 由同一个 runtime/provider factory 携带配置；不新增生命周期 owner 或恢复状态机。

失败语义：真正内容空闲仍携带安全 partial 和原有错误码，走现有有限恢复；人取消仍由 agent loop 终止。显式配置的整请求预算保留原来的失败语义，不承诺从强制取消的请求自动续传。

验证：虚拟时钟验证连续有效进展超过 600 秒仍完成，200 秒内容间隔可接受，元数据不能延长 300 秒空闲预算，取消仍及时；保留显式总预算和重试预算测试。运行受影响 crate 测试与编译、格式闸门。

验证结果：coding 1010 项、harness 248 项测试通过（包含 doctest）；新增 800 秒持续输出、300 秒内容空闲及及时取消判据使用虚拟时钟。显式总预算与覆盖重试的既有判据仍通过。workspace/feature 编译闸门及其阴性对照、格式和 diff 检查通过。未进行 Windows 或官方通道长请求实测。

提交审计：隔离 worktree 中仅应用本次四个 Rust 文件的修改，36 项 recovery 测试与编译、格式闸门通过；代码与主工作区待提交 patch 完全一致。现有显式 request_secs 覆盖仍生效；若曾临时设置 3600，需删除该覆盖或改为 0 才能采用无总上限策略。
