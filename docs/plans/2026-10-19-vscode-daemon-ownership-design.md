# VSCode daemon 无抢占连接

基线：release/v5.2.4 f89201f33，工作区已有 relay/live API 改动；执行期间另有语言桥接开发，保留其文件与测试入口。保留内置 daemon 的优先级和版本/hash 兼容性校验，不切换成全局 CLI，不改 daemon 本体或 Rust runtime 生命周期。

连接所有权在插件 DaemonProcess，端口与 token 由同一 DaemonClient 维护。先检查当前/配置端口及按内置 build hash 推导的备用端口池，已有兼容服务优先复用。外部版本不匹配或 TCP 占用但不健康时绕开，不 POST /shutdown、不按 pidfile/进程名发信号。多窗口用本机临时 TCP 监听作为启动互斥，OS 在关闭或崩溃时自动释放；锁也被占用时有限等待，再尝试其他候选。端口池有限，失败给出中英文提示；不接管任意未知服务。

启动后再次核验身份，只确认兼容后更新共享客户端端口并清除 token 缓存。旧请求的错误不能向新连接重放。启动失败只允许 SIGTERM 这次 spawn 得到的子进程句柄。插件停用不关闭共享服务，进行中的连接选择不得在停用后启动/切换服务。autoStart=false 可复用服务但不启动。

验证：外部健康/卡死进程保持不变、同版本跨窗口单次启动与备用端口复用、启动互斥释放、停用取消、真实 HTTP 端口/token 切换与旧 401 不重放；运行插件类型检查、现有测试及编译。未做 Windows/CodeArts 真机验证。
