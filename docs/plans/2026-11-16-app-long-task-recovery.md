# App 长任务连接与审批恢复

范围：当前 `release/v5.2.8` CLI 与配套 App。不新增旧 CLI 的协议兼容或版本提示。
检查基线：CLI `97dbd2a36`，实施时工作区前进至 `796015302`；App `master` 的
`e4fba0a`。保留其他任务的修改和实验文件。

## 所有权与根因

- daemon live runtime 仍是会话、待审批请求及审批终态的唯一所有者。
  `/live` 已有 15 秒 SSE 注释心跳，以及重连后的 snapshot / pending request 重放；
  不需要增加第二套审批存储或延长工具执行期限。
- App `AtomLiveClient` 管理流连接，`AtomConnectionController` 管理健康探测和
  UI 连接状态，聊天控制器消费 snapshot 和审批事件。
- 单次健康探测超时原先直接将 App 标为离线，即便 SSE 仍在收心跳。
- 前台恢复同时触发 SSE 重连和健康检查；健康检查晚返回后会清空会话视图，
  覆盖已经重放的审批，而 `live.start()` 对正在运行的订阅是空操作。
- CLI 启动的中继子进程输出原先全部丢弃，因此主日志没有报错不能证明中继正常。

## 行为变化及失败语义

- 健康探测失败时参考 SSE 最近活动，连续三次探测失败且没有近期流活动才显示离线。
  健康接口可达但流超过 45 秒没有活动时重新订阅；流断线沿用客户端退避重连。
- SSE 只限制建连等待 15 秒，不给持续响应体设置总时长限制。
- 同一电脑重连保留视图和审批，切换电脑或身份才清空；健康检查不写会话事实。
  连接代次拦截断开或换端点后迟到的健康响应，旧流关闭不得覆盖新流状态。
- 初次探测失败后，恢复时补取服务端能力；重叠探测合并。
- 审批继续使用现有精确身份及确认流程，不自动批准，不在断网时伪造完成。
- CLI 的 App / WebUI 中继分别写 `logs/{app,webui}-relay-<pid>.log`，追加保留
  同进程重启记录；Unix 新文件权限 0600。日志打开失败写主日志警告，远程接入仍可启动。

## 验证范围

App 回归覆盖模拟一小时静默心跳、连续探测失败、审批重放早于健康响应、探测去重、
换电脑及断开后的迟到响应、首次失败后的能力恢复、SSE 建连超时与持续响应体。
CLI 验证日志双流追加与文件权限，运行受影响 crate 测试、全仓编译门和格式门。
以上不替代手机经官方中继的一小时真机网络验证。
