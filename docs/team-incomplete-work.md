# 团队协作中的未完成工作

成员的写入 scope 是权限边界，不表示范围外的任务已由其他成员负责。成员遇到任务必需但无法处理的工作时，应通过 `tell_parent` 报告受影响的非敏感路径、原因和剩余工作，区分完成、部分完成和阻塞。lead 负责核对任务覆盖范围，自行处理或明确安排成员接手。

当现有 delegated-write guard 实际拒绝写入时，team 自动给 lead 发送一条固定通知，同一成员同一回合的多次拒绝合并为一条。通知不含文件路径、工具参数或原始错误，不表示任务已经完成，也不会替代成员的正常汇报。成员自己由用户发起的回合沿用现有规则：通知作为 team note 保留，不自动唤醒 lead。

自动通知只覆盖真实的写入边界拒绝，不根据工具返回的文字猜测拒绝，也不会上报敏感路径检查的内容。模型未执行工具、也未报告就自行跳过的事项，仍无法自动识别；提示指导可以降低这种遗漏，不能保证消除。

本机制不扩大权限、不改变审批、不自动转派任务、不开放成员直连，也不新增共享任务状态。通知通过现有 inbox 和会话事件日志保留；每回合的去重记录仅随 live 成员保存，停止成员即释放。
