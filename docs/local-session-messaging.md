# 会话引用

历史的 `/peers` 实时通信入口及其本地 socket/收件箱实现已经移除。它仅支持 Unix，而且“向另一个在线会话发消息”与“引用历史内容”不是同一种操作。

现在使用输入框中的 `@`：选择文件或会话。会话候选展示标题与项目位置，选择后通过项目 bucket 和完整会话 ID 绑定来源。WebUI 支持移除引用标签；TUI 可直接删除输入中的引用链接。文件补全保留原有行为。

引用是只读的：发送消息时读取源会话已提交的历史，不切换、恢复或唤醒源会话。Windows、macOS、Linux 共用相同的读取路径。最多引用 4 个不同会话，每个只提供最近 8000 字符的用户/助手正文，显式标记截断，不带工具输出、推理、内部指令，也不递归读取历史中的引用。源存储文件超过 8 MiB 时拒绝读取；读取最多等待 5 秒。缺失、不可读或来自更新版本的源会明确拒绝本次发送。

原始引用形式为 `@[标题](atomcode-session:<project_bucket>/<session_id>)`；标题只用于显示，改名不改变绑定。尚未导入的 legacy JSON 会话、以及受委托的子会话不能独立引用。离线来源无需打开 IDE 或另一个终端。

引用带来的上下文是无权限的历史参考数据，不是当前用户指令，不继承原会话的审批。正在运行的来源只读取其已落盘部分；当前会话正在运行时，带引用的消息按已有上下文消息规则排队到下一个回合，不作为实时 steer。

原有后台任务向发起会话汇报仍走 runtime 的 session-bound note；这条业务路径不属于已删除的终端 peer transport。
