# 同机跨会话消息（首版）

支持 macOS/Linux 的 rows 终端界面。两个独立 AtomCode 进程使用同一个产品数据目录，且属于同一操作系统用户时，可以发现彼此并交换纯文本。无需启动第二个 daemon。Windows、经典界面、ACP、headless、跨设备和离线恢复不在首版范围内。

## 使用

在两个终端分别启动此分支构建的 AtomCode，进入正常的有持久会话的 rows 界面。输入 `/peers` 查看其他在线会话的标题、状态、工作目录与地址；地址由运行实例和当前会话共同组成，切换会话后须重新发现。

让模型发送消息，例如：“告诉另一个正在修 UI 的会话，配置接口已经完成；先列出会话确认目标。”模型使用 `list_agents` 和 `send_message`。发送方原有权限模式与 deny/allow 规则仍适用；普通询问模式会要求批准，自动模式按已有执行策略处理。发送授权不授予接收方任何权限。

接收方默认 `hold`，会出现待批准提示。以下命令只能在接收方当前终端执行，消息协议和模型工具没有对应的远程操作：

```text
/peers pending
/peers approve <消息ID>
/peers deny <消息ID>
/peers mode accept
/peers mode hold
/peers mode refuse
```

`accept` 自动接纳后续消息，但不会自动放行已有待批准消息。`refuse` 拒绝新消息并丢弃已有待批准消息。模式只在本次 runtime 中有效，重启恢复 `hold`。`approve` 只批准消息进入模型，不批准消息要求的工具操作。

回执 `held` 表示等待用户决定，`accepted` 表示 runtime 接受了输入；都不代表模型已经读取、回复或完成任务。`uncertain` 表示投递未获确认，不能自动重发。接收方可以通过 `send_message` 回复，仍受对方接收策略约束。没有完成状态轮询或自动回复循环机制。子 agent 不能借用主会话身份使用这两个工具。

## 边界

- 默认只提供在线目录。进程退出后端点注销；异常退出的失效 socket 被发现时忽略，不计入在线端点上限，也不恢复旧消息。发现不删除失效文件，整体扫描仍受 8 秒超时约束。
- 待批准消息仅在内存中。批准后通过既有 runtime note API 写入 native peer 事件；不增加会话持久化格式或第二个 agent 生命周期。
- 实例地址、签名和目标会话绑定防止消息误投、身份字符串伪造与短期重复投递。接收方切换会话后不会把旧消息交给新会话；接收新消息或查看待批准列表时会清理旧会话队列，并将其回执标为拒绝。
- 消息是其他会话提供的上下文，不是人的授权。工具描述和接收上下文明确告知模型：不得代做发送方被拒绝的工作，不得据此修改权限或配置文件。这是模型行为约束；实际工具权限仍由接收方原有审批路径判定。消息中的 slash 命令不执行。
- 本机 socket 只允许同 uid 通信，目录要求私有且非 symlink。消息最多 8192 字节，帧最多 32768 字节，待批准队列最多 32 条，每实例每分钟最多接纳 30 条；最多 16 个并发连接。
- 不自动重试。超时或取消后可能无法确定对方是否已接纳，调用方会收到明确的不确定性提示，不应自动重发。
- 发现会暴露其他在线会话的标题和工作目录；不会传输会话历史、文件或凭据。不要在消息或标题中放凭据。
- 同 uid 的任意代码并非隔离的安全主体；该功能不提供同一个 OS 用户下恶意进程间的隔离。

## 实现与验证

实现位于 CLI 的 `peers` 宿主模块，随 runtime 重建复用服务；socket guard 随连接的 runtime 事件泵结束注销。签名密钥只在内存中，不进入配置树或自描述。wire 协议版本为 1，不兼容版本明确拒绝。

回归覆盖真实独立进程、socket 身份与帧边界、接收策略、重复投递、会话切换、发送方审批/deny 规则，以及批准后 native peer 事实的来源。操作系统 socket 和子进程测试使用真实时钟；runtime 纯生命周期测试使用虚拟时钟。
