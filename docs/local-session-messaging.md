# 会话引用

历史的 `/peers` 实时通信入口及其本地 socket/收件箱实现已经移除。它仅支持 Unix，而且“向另一个在线会话发消息”与“引用历史内容”不是同一种操作。

现在使用输入框中的 `@`：选择文件或会话。会话候选展示标题与项目位置，选择后通过项目 bucket 和完整会话 ID 绑定来源。WebUI 支持移除引用标签；TUI 可直接删除输入中的引用链接。文件补全保留原有行为。

引用是只读的：发送消息时读取源会话已提交的历史，不切换、恢复或唤醒源会话。Windows、macOS、Linux 共用相同的读取路径。最多引用 4 个不同会话，每个引用总计不超过 8000 字符。优先保留当前有效压缩摘要（最多 3000 字符），剩余预算提供最近的用户/助手正文；不额外调用模型生成摘要。来源中的其他内部消息、工具输出和推理不进入引用，也不递归读取历史中的引用。引用显式标记部分内容、省略的消息数和读取到的事件序号，不能视为源会话的完整记录。

原生事件会话逐行读取并复用权威投影处理压缩与撤销，不再因日志超过 8 MiB 就直接拒绝。扫描上限为每个来源 64 MiB，单条记录沿用存储的 16 MiB 上限，投影前累计保留的序列化数据另有 8 MiB 预算；这些是读取保护，实际进程内存还包含解析和投影开销。单条文本先做有界选取，完整查看或检索更早历史不属于本次引用的覆盖范围。旧快照来源仍保留原有 8 MiB 有界加载，不在引用过程中自动迁移。

读取最多等待 5 秒；源会话正在写入时只有限重试，无法取得读锁时明确拒绝，可稍后重试。缺失、损坏、超出读取预算、不可读或来自更新版本的源都会明确拒绝本次发送，而不是提供未经验证的日志尾部。

原始引用形式为 `@[标题](atomcode-session:<project_bucket>/<session_id>)`；标题只用于显示，改名不改变绑定。尚未导入的 legacy JSON 会话、以及受委托的子会话不能独立引用。离线来源无需打开 IDE 或另一个终端。

引用带来的上下文是无权限的历史参考数据，不是当前用户指令，不继承原会话的审批。正在运行的来源只读取其已落盘部分；当前会话正在运行时，带引用的消息按已有上下文消息规则排队到下一个回合，不作为实时 steer。

原有后台任务向发起会话汇报仍走 runtime 的 session-bound note；这条业务路径不属于已删除的终端 peer transport。

## 按需查询引用中的细节

模型可使用只读工具 `session_reference` 查询当前用户消息明确引用的来源。
例如，先 `@` 选中会话，再询问“查一下 TubeSeq 的最终定义”。无需把完整会话
导入当前上下文，也不会额外调用模型生成摘要。原有项目级 `recall` 行为不变。

工具的 `source` 使用引用中提供的 `bucket/id`，`query` 为最多 256 字符的字面
短语，支持大小写匹配处理。默认 `historical=false` 只查当前有效对话及摘要，
返回命中消息及邻近对话。有关键词时优先选取最近窗口，每页内部按消息位置排序；
无关键词时按时间顺序分页。超长消息选取靠近最后一次命中的窗口；结果会标注部分
内容，不能把未命中解读为整个原始历史中从未出现过。

只有追溯原始讨论时才使用 `historical=true`：它读取原始用户/助手消息记录，
其中可能包含已经被压缩替代或撤销的旧方案，响应会明确标注，不能作为当前结论。
两种模式都不返回工具输出、工具参数和推理内容。旧快照暂不支持详细查询。

每次最多 10 条消息、正文累计最多 16000 字符。`position` 是该读取版本的消息
位置，不是回合号。`offset` 是查询结果的分页位置，不直接等于消息的 `position`。分页使用响应中的
`next_offset` 和 `captured_through_seq`，
并保持相同的来源、查询与历史模式；源会话发生变化时会拒绝续页，需从零重查。
读取仍受前文的文件、记录、保留预算和五秒超时限制。

授权从当前回合最新的人类消息提取，不接受助手、同伴注入或历史引用正文中的
伪造链接；下一回合需要重新携带引用。委派成员不继承主会话的引用授权，应由
主会话查询后按任务需要提供片段。禁用工具时，此工具也不会发布到模型目录。
