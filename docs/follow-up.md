# 一次性后续任务

主 CLI/TUI/WebUI 支持用户预设的一次性同会话 follow-up：

```sh
# Headless：两步都执行结束后才返回最终退出状态
atomcode -p '实现这个修复' --follow-up '检查刚才的修改，补跑必要测试并总结'

# TUI / WebUI 输入框
/followup set 检查刚才的修改，补跑必要测试并总结
/followup show
/followup clear
```

空闲时登记，作用于下一次通过普通消息入口提交的人工任务；运行中登记，作用于当前任务。通知、自动输入和本地命令不会领取空闲登记。若希望接在技能/目录命令唤起的任务后，请在该任务运行时登记。重复 set 替换原登记。prompt 最大 16 KiB UTF-8，不允许空白。登记后再次提交人工输入会撤销已经绑定当前任务的旧登记，以新指令优先。

只有正常停止、没有待答请求/未收取的后台任务、持久化没有失败时才执行。取消、错误、预算耗尽等终态不执行；相应登记被消费或清除，不会在以后的任务上突然触发。这里的“正常结束”不是业务成功判定，不能据此推导“测试通过，所以可以部署”。

后续 prompt 在同一会话、相同模型和权限模式下执行，正常经过 hooks、工具权限和审批。权威历史中的输入带“Automatic follow-up / 自动后续任务”标识，执行前也会显示提示。它是用户预设输入，会应用现有的每轮执行限制；不会升级权限。原任务与 follow-up 作为一个受管理操作完成，headless 调用会等待两步结束，退出状态反映最终执行终态。

登记在提交后续输入之前即被消费；后续任务不会因为自己的完成而再次触发它。goal/loop 与待执行的 follow-up 互斥，需先停止 goal/loop 或撤销登记。取消、会话/目录切换以及导致 generation 改变的 runtime 重建会清除登记。

此版本只在当前进程保存登记，不支持重启恢复、新会话 action、定时任务链、条件分支或持久 DAG。WebUI 只管理当前已绑定的会话，浏览其他历史会话不会改绑运行时，也不能为它登记。
