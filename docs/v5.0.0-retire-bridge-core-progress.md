# v5.0.0 — 退役 bridge/core：进度与路线图

> 目标：完成 v1→v2 迁移，最终删除 `atomcode-bridge`(strangler 缝合层）与 `atomcode-core`
> (v1 引擎)。策略：**从易到难、小步可验证、每步保持 workspace 绿且行为一致**。
> 分支 `release/v5.0.0`（基线 `0c08496b` / release/v4.26.1）。

| C+E：core 内部+测试切走 + **删掉 config/locale 垫片** | `02e66d26` | — |

**影响的功能（config 抽取，行为全部 byte-identical）**：
- **配置加载/保存**：`Config::load/save`（含 6 个手写 section 渲染器：datalog/notifications/network/telemetry/instructions/hooks）、`default_path`、`config_dir`（`$ATOMCODE_HOME` / sudo 感知 home）、首次运行 seed

## ⏳ 待完成

### 四、core 外围模块外迁（config 抽取后新解锁的）

`config` 出 core 后，之前"因依赖 config/proxy 而搬不动"的模块现在有了前提。真正 core-内部零引用、可外迁的：

| 模块 | 外部引用 | 依赖 | 目标家 | 影响的功能 |
|---|---|---|---|---|
| `self_update` | 30(tuix17/cli13) | config+proxy(已在 config) | 新 crate 或 cli/tuix | **自动更新**：检查/下载/安装新版本 |
| `notify` | 19(tuix17/cli2) | agent+config | 新 crate 或 tuix | **桌面通知**：回合完成提醒 |
| `auth` | 37 | config 等 15 内部 | 新 `atomcode-auth` | **登录/凭据**：OAuth、token |
| `i18n` | 23 | 被 core 内部大量使用 | 新 `atomcode-i18n` | **本地化字符串** |
| `setup`/`locale(已搬)`/其它 | 小 | — | — | 首次配置向导等 |

> ⚠️ 仍被 core 内部承重的（proxy/process_utils/ctx 等）**要等 core 整体退役才能删**——它们是 v1 引擎的一部分。

### 五、驱动协议迁移（退役 bridge 的真正解锁点，最大一块）

bridge 用 core 的 v1 channel 协议（`AgentClient/AgentCommand/AgentEvent`）对外、v2 栈对内。要删 bridge，必须让驱动直接说 **kernel 原生协议**（`atomcode_kernel::event`）：

| 驱动 | 耦合 | 影响的功能 | 风险 |
|---|---|---|---|
| **daemon**（建议先做 PoC） | 65 处/1 文件 | **webui 后端**:流式/审批/持久化 | 中(单文件、最小协议面；`cli/src/acp/` 已是现成 kernel 原生模板) |
| cli headless | 89 处/4 文件 | `-p` 无头运行 + TUI 启动 | 中(main.rs 仍跑 v1 引擎) |
| **tuix** | 201 处/7 文件 | **整个交互式 TUI**:事件循环/渲染/goal/loop/undo/compaction… | 高(用尽 bridge 自造的 ~15 个功能) |

> bridge 自身还扛着 ~15 个 kernel 没有的驱动级功能(goal/loop/undo/plan-mode/memory/background/local-shell/会话持久化/context-stats/compaction-UI),迁移时要逐一在驱动或 coding 层重实现。详见 `docs/superpowers/plans/2026-07-11-retire-bridge-and-core.md`。

### 六、最终删除

- 所有驱动不再用 bridge 后 → **删 `atomcode-bridge`**
- config 及外围模块出 core、驱动迁移完成后 → **删 `atomcode-core`**(含 v1 引擎、`agent`/`conversation`/`tool`/`session` 等协议核心、`graph`/`semantic`/`trace` 等 0 外部引用但 core 内部承重的模块)
- **删 `--engine v1` / `$ATOMCODE_ENGINE=v1` 逃生舱**(`cli/src/main.rs`)及相关文档

## 迁移原则(贯穿始终)

1. **每步 workspace 绿 + 行为一致**,单独 commit,只 stage 本步文件
2. **re-export 垫片**过渡:搬走那一刻旧路径仍解析,再逐个切消费者,最后删垫片
3. **类型↔运行时拆分**:含重依赖(reqwest)的模块只搬"配置类型",运行时留原处 re-export
4. **叶子 crate 无环**:抽出的共享物只依赖更底层,任何层都能用
