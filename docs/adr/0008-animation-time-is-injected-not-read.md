# 动画与时间由宿主注入,render 永不读系统时钟

状态: 提案中

## 背景

有模块需要随时间变化而不等事实到达:动画吉祥物、思考中的转轮、
「距离限流重置还有 30 秒」的倒计时。

而 TUI 的整套自动化闭环建立在确定性上:回放 provider、无头终端、
`start_paused` 的时间、静默判据。**只要有一处读了墙钟,闭环就废了——
而且是静默地废**:测试还在跑,只是不再可靠。

人有先验知识能过滤偶发的红,Agent 没有:它会把抽风当真信号去修不存在的 bug,
或者直接把那条测试删掉。

## 决策

**时间是 `Moment` 的字段,由宿主注入;`render` 永不读系统时钟。**

`Moment` 的定义本来就是「不可推导的环境」(终端尺寸、agent 状态、半截输入、
焦点)。时间正是这一类,所以这不是加概念,是把一个空着的槽填上:

```rust
pub struct Moment {
    pub status: AgentStatus,
    pub input:  String,
    pub focus:  Option<ModuleId>,
    pub scroll: ScrollPos,
    pub tick:   u64,          // 逻辑帧计数：动画相位
    pub now:    Timestamp,    // 注入的时刻：倒计时等需要真实间隔的场景
}
```

模块声明自己需要按时间重画,宿主取所有声明的最小周期驱动:

```rust
fn tick(&self) -> Option<Duration> { Some(Duration::from_millis(120)) }
// None（默认）= 只在事实到达时重画
```

动画模块的状态因此分成两半:**情绪来自事实**(`absorb` 折叠),
**相位来自 `tick`**(render 的输入)。`render` 仍是纯函数——
同样的 `(state, tick, now, rect)` 给同样的输出。

执行者:`render` 的签名里没有 `Context`、不是 async、拿不到任何 IO,已经堵死大半;
剩下的靠 `tui` crate 内禁用 `Instant::now` / `SystemTime::now` 的 lint。

## 放弃了什么

**在 `render` 里直接读墙钟。** 最省事,不用把时间一路穿过 `Moment`。
放弃是因为它**静默地**毁掉整个闭环:测试仍然绿,只是同一份输入不再给同一份输出。
代价是 `Moment` 多两个字段,且每个动画模块都要从参数里取时间而不是就地读。
**这个「啰嗦」正是下一个人会想简化掉的东西——这份记录就是拦他用的。**

**把动画帧做成日志事实(`SessionEvent::Tick`)。** 这样 `render` 依然纯粹是
折叠出来的状态的函数,接口一个字段都不用加。放弃是因为会话日志是**durable**
且被持久化、模型投影、恢复共用——往里面灌每秒 8 帧的动画心跳,
是拿一个共享的、要长期保存的东西去解一个纯呈现问题。
代价:失去了「所有 render 输入都来自日志」这个更整齐的说法。

**模块内部可变状态自增(interior mutability 自己动)。** 不改任何接口。
放弃是因为它直接破坏纯度:同一个状态连画两次给出不同结果,
一致性套件里的「确定性」那一条当场失效,而那条是其余判据的地基。

**宿主持有每个模块的动画状态机。** 把动画收归宿主管。放弃是因为宿主要因此
知道各模块的动画语义,而「宿主不认识任何模块」是空间可组合性的前提。

## 失效条件

- 若模块数量增长到「取所有周期的最小值」造成过度重画,
  需要 per-module 的 tick 调度,而不是全局节拍。
- 若出现需要亚帧精度或与真实墙钟严格同步的场景(例如与外部录制对齐),
  注入的 `now` 可能不够,需要重新评估——但**任何替代方案都必须保住
  「测试里时间可注入」这一条**,否则闭环不成立。
- 若动画被证明在真实使用中只是干扰(用户普遍关掉),
  `tick` 机制的存在价值需要重估。
