# Skill 目录与加载状态

默认扫描目录保持不变。要读取其它位置的 skill，在正在使用的 `config.toml` 中添加：

```toml
[skills]
extra_dirs = [
  "~/.codeartsdoer/skills",
  "~/.codebuddy/skills-marketplace/skills",
]
```

填写包含 `<name>/SKILL.md` 的父目录；也支持现有的单文件 Markdown 模板。AtomCode 直接读取这些文件，不复制、不改写，也不自动接入其它工具的目录。仅加入你信任的目录：skill 可以包含 shell 预执行、脚本和工具授权声明，原有权限与审批规则仍然适用。

## 路径与优先级

- `~` 指当前用户的主目录；不支持 `~other-user` 或环境变量插值。
- 相对路径以会话工作目录为基准。Windows 路径可以使用 TOML 单引号，例如 `'C:\Users\me\skills'`，避免反斜杠转义。
- 额外目录先扫描，默认目录随后扫描；同名 skill 的默认来源优先。额外目录之间，列表中后面的优先。插件仍保留自己的命名空间和已有优先级。
- 已存在目录的重复路径、符号链接别名会去重，并保留优先级更高的位置。
- 缺省为空。宿主显式指定完整扫描列表或禁用 skill 时，保持宿主选择。

配置文件重新读入后，新目录才会进入运行时。终端 UI 的 `/reload` 会检查配置变化；配置未变时，轻量重载只重新读取已配置目录中的 skill。新启动的运行时也会读取配置。

## 分组、依赖与符号链接

技能可以放在多层分组目录中；遇到含 `SKILL.md` 的技能目录后，不再扫描它的资源子目录。
自动发现会跳过 `.venv`、`venv`、`node_modules`、`.git`、`.hg`、`.svn`、
`__pycache__`、`.pytest_cache`、`.mypy_cache`、`.ruff_cache`、`.tox`、`.nox` 子目录，
避免把运行依赖及其示例当成技能，也避免遍历整个 Python 虚拟环境。
这不是跳过所有隐藏目录：`.system` 等正常技能分组仍会发现；显式配置的扫描根目录不受名称过滤。

符号链接安装仍受支持。扫描按当前路径的真实目录祖先检测循环，遇到循环立即停止该分支；
独立的技能分组深度限制仍保留。普通目录过深只提示深度上限，只有实际检测到循环才提示符号链接循环。
扫描不会删除、修改虚拟环境，也不影响已加载技能运行其中的脚本。

## 诊断与生效时机

显式配置的目录不存在、目录读取失败或 skill 解析失败时，会显示路径和原因。默认兼容目录不存在是正常情况，不告警。轻量重载不重复报告未变化的失败；修复后诊断消失，之后再次发生会重新报告。同名覆盖保留在状态详情中，不当作启动错误。

`/status` 中的指令和 skill 来源反映运行时实际加载记录。指令正文在当前上下文创建时读取，不监视磁盘。文件编辑、更名或删除后，状态详情会标出磁盘变化，当前已加载的旧指令仍保留。轻量 skill 重载不刷新指令正文；恢复会话或完整重建运行时会重新加载指令。

同目录的项目指令按 `.atomcode.md`、`ATOMCODE.md`、`AGENTS.md`、`CLAUDE.md`、`claude.md` 的顺序选择首个存在文件。其余候选会提示被遮蔽。所选文件为空或不可读会单独提示，保持原有不回退语义。大小写不敏感文件系统上指向同一文件的候选不重复报告。

实际加载的全局、项目和用户指令正文合计超过 16 KiB 时，启动诊断会列出来源路径、各文件及合计的 UTF-8 字节数和字符数。它是体积提醒，不是 token 计数或新的截断预算；被遮蔽、缺失或不可读的文件不计入。提醒不会改写文件或改变注入内容。已有长文件是否精简由用户决定。

`/init` 生成或维护指令时应保留当前有效规则，用当前事实替换过期表述；事故复盘、性能实验和已完成迁移的详细过程放在有链接的文档中。迁移或删除已有文件内容前需用户明确同意，不能为满足篇幅目标而静默摘要、截断或丢弃规则。

本功能不包含外部工具自动探测、迁移体检、自动转换、私有索引或会话历史导入。
