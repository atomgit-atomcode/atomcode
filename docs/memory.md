# 记忆摘要与按需知识库

`memory.md` 保存短的长期事实和偏好。全局、项目、本机三层记忆及可选知识索引共用 4000 字符预算；单条记忆注入上限为 500 字符，索引正文上限为 1000 字符，说明和路径也计入总预算。置顶活跃条目先分配预算；同等置顶级别内优先选本机、项目、全局，各层优先较新的行。磁盘源文件不因预算截断而修改。

## 查看实际注入状态

运行 `/memory`。TUI 默认打开「注入状态」，另外保留三层完整源文件标签。CLI 的文本输出与 `/memory --json` 使用同一份派生报告；JSON 保留原有源文件数组，在首个 section 上增加可选 `review` 字段。

报告分两部分：

- **会话日志中的记忆**：已记录的注入原文、是否仍在投影上下文中，以及是否与磁盘最新预览一致。未开始首回合时，明确标注运行时装配时准备的内容；关闭注入时也明确说明。
- **磁盘最新预览**：三层记忆的选中、省略和缩短条目，知识索引是否纳入，以及读取失败、部分读取等原因。

新会话的首回合通过现有事件日志注入一次。`/remember`、`/forget` 或手工修改文件不会重写已有会话的注入消息；resume 保留历史日志。需要使用新的常驻内容时，启动新会话。按需读取文件仍可以获得最新内容。

有省略、缩短、读取失败或部分读取时，记忆注入卡片的标题会提示「记忆未完整加载」，并引导使用 `/memory`。此提示随原注入日志回放，不把磁盘新状态冒充旧会话状态。

超过 64 KiB 的记忆源使用末尾完整行和额外有界扫描的置顶候选参与预算选择，报告会明确说明计数没有覆盖所有条目。非法 UTF-8 和无法读取的文件会报告错误，不会伪装为空记忆。

## 启用项目知识库

默认在宿主提供的项目设置目录中发现 `knowledge/INDEX.md`。以默认产品名为例：

```text
.atomcode/
  memory.md
  knowledge/
    INDEX.md
    architecture.md
    troubleshooting.md
```

目录不会自动创建；索引不存在或为空时不启用知识库。将长知识放入主题文件，在索引中写清描述、适用场景和路径，例如：

```markdown
# 项目知识

| 主题 | 适用场景 | 文件 |
| --- | --- | --- |
| 运行时所有权 | 修改会话、取消、恢复 | .atomcode/knowledge/architecture.md |
| 构建排障 | 构建或测试失败 | .atomcode/knowledge/troubleshooting.md |
```

索引使用项目根目录相对路径或明确的绝对路径，避免模型误解相对路径基准。只有有预算上限的索引进入常驻上下文；链接文件不会递归加载，模型通过现有文件读取和搜索工具按需查阅。索引超限也会显示警告，可按需读取完整索引。读取正文仍遵守既有工具权限，索引不会增加权限。

已有自定义知识库可以在 harness 配置的 memory 行指定 `knowledge_index`（相对路径以项目根目录为基准）：

```toml
[[patch]]
id = "memory"
config = { knowledge_index = ".atomcode/记忆库/SKILL.md" }
```

这是 harness 行配置，不是新的顶层 `config.toml` 字段。新配置应保留该行原有的 `project_root` 等宿主参数。

## 当前范围

记忆作为可能过时的背景事实，不获得高于当前指令的权限。保留可人工编辑的 Markdown 格式，支持显式的条目元数据和精确管理；不自动搬迁、提炼、修改或删除知识，支持可恢复的显式 TTL，不自动生成或校验索引链接，也不保证模型每次都能选中正确文件。当前任务执行状态继续由会话日志和现有任务机制管理。

## 条目元数据与精确管理

新条目有随机生成的稳定 ID、UTC 创建/更新时间，以及可选的主题和来源、状态、置顶标记。正文只保存一份，元数据放在同一行的版本化 JSON 注释中，例如：

```markdown
- 运行时只有一个会话 owner <!-- atomcode-memory:v1 {"id":"m-example","created_at":"2026-10-21T01:00:00.000Z","updated_at":"2026-10-21T01:00:00.000Z","topic":"runtime","source":"docs/adr/0024","status":"active","pinned":true} -->
```

上面的 ID 仅为格式示意，正常写入由程序生成。元数据不进入模型常驻正文，也不占用记忆正文的字符预算；`/memory --json` 的 section 增加 `entries` 数组，供程序读取结构化条目。TUI 的来源页会先列出带 ID 的条目目录，再显示原始文件，方便精确管理。

旧 `- 正文` 条目不需要迁移：读取时不写盘，创建/更新时间保持未知，不从文件 mtime 猜测。旧条目的暂存 ID 由内容确定，首次精确修改时连同元数据一起固化，之后修改正文也保持这个 ID。完全相同的旧重复条目会产生歧义，程序拒绝按 ID 猜测修改哪一条；应先手工区分它们的正文。未固化元数据前，手工改正文会改变这个内容派生 ID。

常用命令：

```text
/remember --topic runtime --source docs/adr/0024 --pin 运行时只有一个会话 owner
/memory --topic runtime
/memory --json --project --topic runtime --status active
/memory pin <ID>
/memory unpin <ID>
/memory update <ID> --topic architecture 新的准确描述
/memory update <ID> --clear-source
/memory deprecate <ID>
/forget --id <ID>
/memory update <ID> --status active
```

`--global`、`--project`、`--local` 选择范围；按 ID 修改默认只作用于项目层。例如全局记忆应使用 `/memory --global pin <ID>`。ID 应与所在范围一起使用。

元数据选项放在正文前面；主题和来源支持单引号或双引号包围的值，不执行任何 shell 展开。`--clear-topic` 和 `--clear-source` 清除对应元数据。使用 `/remember -- --pin 是正文的一部分` 可以记录以选项开头的文字。

状态为 `active`、`outdated`、`deprecated`。后两者保留内容和 ID，但不参与常驻注入；管理器会把它们写成 `> - 正文 <!-- 元数据 -->`，使旧的 bullet-only 读取器也跳过它们。恢复为 `active` 后重新具备注入资格。修改磁盘上的条目仍不会改写当前会话日志，只有新会话按最新状态和期限选择常驻记忆。

`/forget --id` 是精确、可逆的废弃；原有 `/forget <关键词>` 仍是实际删除，只匹配正文，不匹配 ID、主题或来源。无范围时关键词删除扫描三层；显式指定范围时只删除该层。需要保留历史时应使用按 ID 废弃。

置顶的活跃条目先于普通条目和知识索引分配预算。置顶之间仍按本机、项目、全局的顺序，各层优先较新的行；置顶不是无限预算，放不下的条目仍明确报告为省略。过时、废弃属于有意排除，不算预算溢出。

大文件使用有界候选集：普通条目保留尾部 64 KiB；另行流式扫描置顶条目，最多保留 64 KiB 置顶候选，使较早的置顶条目也能参与选择。超出候选窗口仍显示部分读取提示；超过 64 KiB 的单行在此扫描中会明确报错，需拆成短摘要或移入知识库；托管写入也会拒绝超过读取边界的条目。

托管写入通过相邻、自动忽略的 `.memory-locks/` 目录中的文件锁串行化，使用同目录临时文件原子替换，并保留已有文件权限。外部编辑器不参与这个锁，提交前会比较源内容；已检测到的并发外部修改会中止写入，不能把它当作跨编辑器事务保证。损坏或未知版本的元数据会报错并拒绝修改，不能静默回退成活跃条目。

## 可恢复的到期时间（TTL）

默认永久保留注入资格，不给旧条目补造期限。需要时明确指定整数天数（1 至 36500 天，每天 24 小时）：

```text
/remember --ttl-days 7 临时迁移期使用兼容接口
/memory --expired
/memory --expiring-within 7
/memory update <ID> --ttl-days 14
/memory update <ID> --clear-expiry
```

`ttl_days` 在写入时换算为 UTC `expires_at`，只保存绝对期限；不因读取、正文更新、置顶或改状态而自动延期。到达期限（含等于期限）就失去新会话注入资格，置顶也不例外。条目状态仍保留，过期不等于废弃，不自动改写或删除文件；延期或清除期限后，活跃条目重新具备注入资格。废弃/过时条目还需要显式恢复 `active`。

`--expired` 列出所有已到期的条目；`--expiring-within N` 列出尚未到期且将在 N 天内到期的活跃条目，包含窗口末端。两者互斥，可以与主题、状态和范围筛选组合。到期条目不会计入预算溢出数量，诊断明细显示“已过期”和实际期限。

工具对应参数为 `ttl_days`、`clear_expiry`（只用于更新）、`expired`、`expiring_within_days`（后两项只用于列表）。延期必须按 ID 显式更新，重复 remember 不会悄悄改变原条目的期限。

当前会话里已经记录的注入事实继续保留，TTL 不追溯撤销历史消息。新会话使用装配时的期限选择；`/memory` 展示查询时的磁盘状态，和当前会话历史分开展示。此阶段没有后台定时清理或自动提炼。

## 网页端和无状态命令接口

网页端通过 daemon `POST /command` 使用同一套参数解析与记忆工具，支持主题、期限和按 ID 管理。旧请求保留 `remember`、`forget`、`memory` 响应种类；`remember` 和 `memory` 增加可展示的 `text`，新管理操作和筛选使用 `memory_action` 携带 `text`。旧数组字段仍提供活跃正文，完整列表文字同时展示保留的非活跃条目和 ID。

该无状态接口只报告磁盘内容，不声称掌握运行中会话的注入状态；HTTP 响应始终使用该接口的 JSON envelope。前文带 `review` 的 `/memory --json` section 数组属于运行时命令接口，TUI 的「注入状态」也来自该运行时接口。
