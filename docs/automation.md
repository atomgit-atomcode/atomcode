# 自动化任务

`/schedule` 和 WebUI 侧栏的「自动化任务」使用同一份任务目录。
WebUI 的「新建任务」会打开一个新对话并预填创建请求，不自动发送；也可选择「手动配置」。
界面沿用模型设置的弹窗、任务卡片与确认样式。可按名称、指令、工作目录搜索，
筛选全部、已启用和已暂停任务；启用任务优先按预计下次运行时间排序。
可以编辑、暂停、立即运行、查看历史和打开运行会话。TUI 使用方向键与
Enter 操作，创建与删除须确认；Esc 取消表单。CLI 保留 `atomcode schedule`
命令，并增加 `edit` 和分页 `history`。

模型可调用 `schedule_list/create/update/delete` 管理当前项目的任务。
更改持久任务必须获得人工批准；Plan 模式只允许查询，不允许修改持久任务。
无交互执行和默认子 agent 不提供这些管理工具。
任务定义不保存 API key，执行沿用主机配置的默认模型。

## 运行与时间

每项任务拥有一个固定的原生会话：首次执行创建，后续触发恢复同一会话并追加新回合，
上下文随之延续，并沿用正常的上下文压缩机制。TUI 恢复列表和 WebUI 侧栏显示自动化标识。
通过既有系统调度器触发，关闭 TUI 或浏览器不会取消已注册任务。
暂停、删除只阻止后续触发，不取消正在运行的会话，也不删除已有对话。

已有任务沿用最近一次已记录的执行会话；此前的其他会话保留，不合并、不删除。
绑定会话被删除、损坏、被其他运行时占用或不兼容时，本次执行明确失败，
不会静默新建或分叉；打开同一会话查看历史不占用执行权，TUI 恢复会话则会取得租约。
任务绑定后不能通过更改工作目录把对话移到另一个项目；需要更换项目时应新建任务。
创建任务时的对话不自动成为任务执行会话。

支持每日、每周、整点和固定分钟间隔。使用**执行主机本地时区**，不是手机时区；
下一次运行时间是估计值，实际触发、夏令时和关机后的补跑以系统调度器为准。
不支持任意 cron、一次性提醒和任意 IANA 时区，不能把它们静默转换成近似规则。
自动权限沿用现有无人值守限制，最多 AcceptEdits；需要交互批准的工具操作失败关闭。

## 状态和恢复

「已保存」「已启用」「系统已注册」「运行中」分别展示。注册失败仍保留定义，显示
错误，可显式修复注册；无法查询系统状态时显示未知。删除时系统清理失败会给出警告。

编辑使用所见修订号，修改先保存在草稿中，通过「保存更改」一次提交；「取消」恢复
已保存内容。每天与每周之间切换会保留已选时间。刷新会同步未编辑字段并保留本地修改；同一字段发生并发变更时阻止覆盖，
必须核对最新版本。离开未保存的草稿会提示确认。

仅更改名称、指令或权限不会重新注册系统定时器；等价规则和无变化的保存也不会
重置计时。改变固定间隔或重新启用时，以接受保存的时间作为新的预计计时基准；
实际触发仍由系统调度器决定。暂停任务修改规则不会触碰系统注册。
Linux 间隔定时器提供独立的首次触发条件，调整时只重启 timer，不停止运行中的任务。
系统对激活时间和上次运行时间的定义见 [systemd.timer](https://www.freedesktop.org/software/systemd/man/257/systemd.timer.html)。
每个任务使用进程租约防止重叠执行；重复的手动请求不会再次启动任务。启动结果无法
确认时标为 uncertain，不能靠自动重试宣称执行一次。系统触发的时机由系统管理。

运行历史独立追加，保存当次指令、修订、原生会话和终态。完成不会覆盖后续编辑，
也不会恢复已删除任务。崩溃留下的未结束运行在租约释放后标为中断。
定义文件兼容既有 JSON；历史与请求收据保存在 schedules 下的 runs/receipts 目录。
原生事件会话仍是对话内容的唯一权威。

目录与历史记录在加载失败时保留已显示的内容，并提供重试；不会把失败显示成空列表。
删除确认固定弹窗打开时的修订号，后台刷新不会悄悄改变待删除目标。删除失败可在
确认弹窗内重试，成功后以刷新结果更新目录；确认弹窗的键盘焦点保持在弹窗内。

## 架构与验证范围

atomcode-schedule 是 CLI 与 daemon 共用的本地主机服务，接收宿主给定的目录；
capabilities 只依赖注入的接口，coding runtime 继续拥有 agent 生命周期。
浏览器仅观察变更和提交明确操作，不运行调度计时器。

自动测试使用临时目录、注入的系统命令执行器和本地模拟接口，不注册真实系统任务。
macOS launchd、Linux systemd 和 Windows Task Scheduler 的命令生成与失败语义均有
测试；实际设备上的触发、休眠唤醒、系统账户权限仍需平台验收。
