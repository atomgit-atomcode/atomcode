1. 架构设计

1.1 一句话

所有模型共享一个 trait CtxBuilder，每个模型可选择实现自己的 context 构造逻辑；没实现 → 走 DefaultCtx。

1.2 设计原则

原则 含义
单一 trait 不拆 role、不做 facade 聚合。CtxBuilder 5 个方法，一个 impl 一套完整行为
impl 自主 trait 只定接口、不强制流程。build_messages 里爱怎么构造消息都行——改 system prompt、砍 tool schema、自定义 turn_reminder、自创压缩规则
默认兜底 DefaultCtx 完全等价原有 Conversation::to_provider_messages_budgeted 行为。规则表未命中的模型永远走它
YAGNI trait 只有 5 个方法、数据契约只返回 (Vec<Message>, ContextStats)。不预留字段、不预留枚举变体，等真需要再加
按 provider 构造 注册入口 for_provider(&ProviderConfig)，impl 从 config 里捕获 ctx_window / max_tokens / base_url 等所需字段
跟随模型切换 ReloadConfig 重建 ctx；build_system_prompt() 已经每轮重建、按 provider 读字段——两层自然协同，无需特殊握手

1.3 Trait 长这样

pub trait CtxBuilder: Send + Sync {
    /// 构造这一轮发送给 LLM 的消息数组 + 统计。
    /// impl 完全自主决定怎么组装——system prompt 要不要变、
    /// tool_result 要不要压、turn_reminder 要不要注入。
    fn build_messages(
        &self,
        conv: &Conversation,
        system_prompt: &str,
    ) -> (Vec<Message>, ContextStats);

    /// 是否触发压缩(每轮末检查)。默认：不压。
    fn needs_compression(&self, _: &Conversation, _: usize) -> bool { false }

    /// 压缩计划(待摘要文本, 删几条)；None = 不压。
    fn compression_plan(&self, _: &Conversation) -> Option<(String, usize)> { None }

    /// 单条 tool 输出截断。
    fn truncate_tool_output(&self, result: &mut ToolResult, tool_name: &str);

    /// 策略名(日志/调试)。
    fn name(&self) -> &'static str;
}
为什么 build_messages 一个方法就够—— 它直接拿到 system_prompt: &str（来自 agent::prompt 层，已按 provider 重建）。impl 想改 system prompt 自己变换即可；想自定义 tool_result 压缩、turn_reminder 注入时机、replace_stale_reads 策略， 全部在 build_messages 函数体内决定。

不需要额外的 transform_system_prompt / build_cold_zone / build_hot_history 钩子—— 那些都是没证据支撑的过度设计。真需要时再加。

3. 关键时序

3.1 启动：config → CtxBuilder

图 3.1 — AgentLoop::new 只调一次 for_provider，拿到 Box<dyn CtxBuilder> 存在 self.ctx。整个 session 期间除非 ReloadConfig，否则不再换。

3.2 每轮：render 与 LLM 调用

// 已按 provider 重建 build_messages(&conv, &system_prompt) ── DefaultCtx: 透传 conv.to_provider_messages_budgeted ── 自定义 impl: 自由变换 system_prompt + 组装 messages (Vec<Message>, ContextStats) turn_runner.run(messages, ...) chat_stream(messages) StreamEvent::Delta / ToolCall ... truncate_tool_output(&mut r, name)
图 3.2 — AgentLoop 每轮：先让 agent::prompt 构 base system_prompt（已按当前 provider），再交给 self.ctx.build_messages 组装最终消息数组。TurnRunner 拿结果跑 LLM。工具结果回流走 self.ctx.truncate_tool_output。

3.3 压缩：策略决策 + 数据层应用

图 3.3 — 压缩分两步：ctx 决策（是否压、压什么 content、删几条）+ agent 执行（真调 LLM 摘要 + Conversation 应用变更）。关键分工：ctx 不调 LLM 不动数据，Conversation 不懂策略。

3.4 切模型：ReloadConfig 同步重建 ctx

// 读新 provider
图 3.4 — 用户 /model 切模型时：AgentLoop 一行 self.ctx = for_provider(...) 完成策略层切换。下一轮 turn 开始时 build_system_prompt() 本来就是每轮重建的，自然读到新 provider。两层自动协同。

4. 实例：如何加自定义 ctx

本节 3 个真实例子，展示不同粒度的定制。全部可复制粘贴。

4.1 例：OllamaCtx — 小窗口激进截断

需求：本地 llama3/qwen 在 8K 窗口下跑。标准 tool schema 太长（占 2K+），bash 输出占 32K 上限太宽松。需要整体裁。

步骤 1：新建 crates/atomcode-core/src/ctx/ollama.rs

use super::CtxBuilder;
use crate::config::provider::ProviderConfig;
use crate::conversation::{ContextStats, Conversation};
use crate::conversation::message::Message;
use crate::tool::ToolResult;

pub struct OllamaCtx {
    ctx_window: usize,
}

impl OllamaCtx {
    pub fn new(p: &ProviderConfig) -> Self {
        Self { ctx_window: p.context_window.max(4000) }
    }
}

impl CtxBuilder for OllamaCtx {
    fn build_messages(
        &self,
        conv: &Conversation,
        system_prompt: &str,
    ) -> (Vec<Message>, ContextStats) {
        // 1. 砍 system prompt 里的 tool schema 长描述(每个工具只留名称+一行 usage)
        let trimmed = strip_verbose_tool_schemas(system_prompt);

        // 2. 调 legacy 底层走窗口裁切，拿到基础消息数组
        conv.to_provider_messages_budgeted(&trimmed, self.ctx_window)
    }

    fn needs_compression(&self, conv: &Conversation, sys_tokens: usize) -> bool {
        // 小窗口更激进：40% 就触发(默认 50%)
        let total: usize = sys_tokens
            + conv.messages.iter().map(|m| m.estimate_tokens()).sum::<usize>();
        total > self.ctx_window * 40 / 100
    }

    fn compression_plan(&self, conv: &Conversation) -> Option<(String, usize)> {
        let (content, n) = conv.build_compression_content();
        if content.is_empty() || n == 0 { return None; }
        Some((content, n))
    }

    fn truncate_tool_output(&self, result: &mut ToolResult, tool_name: &str) {
        // Ollama 下 tool_result 更紧：4K 字节上限(DefaultCtx 是 32K)
        super::truncate::truncate_output(result, tool_name, self.ctx_window);
        const SMALL_CAP: usize = 4000;
        if result.output.len() > SMALL_CAP {
            let mut cap = SMALL_CAP;
            while cap > 0 && !result.output.is_char_boundary(cap) { cap -= 1; }
            result.output.truncate(cap);
            result.output.push_str("\n[... truncated by OllamaCtx ...]");
        }
    }

    fn name(&self) -> &'static str { "ollama" }
}

fn strip_verbose_tool_schemas(sys: &str) -> String {
    // 业务实现：按正则砍掉 === TOOL SCHEMAS === 到下一个 === 之间的大段文字，
    // 只保留每个工具名 + 一行 usage。具体取决于 system prompt 模板结构。
    sys.to_string()   // 示意
}

步骤 2：在 ctx/mod.rs 声明 + ctx/resolver.rs 注册

// ctx/mod.rs: 加一行
pub mod ollama;

// ctx/resolver.rs: 在 for_provider 里加分支
pub fn for_provider(provider: &ProviderConfig) -> Box<dyn CtxBuilder> {
    if provider.provider_type == "ollama" {
        return Box::new(super::ollama::OllamaCtx::new(provider));
    }
    // ...其它规则...

    Box::new(DefaultCtx::new(provider))
}

就这三步。

用户配 provider_type = "ollama" → 自动走 OllamaCtx。其它 provider 不受影响。

4.2 例：ClaudeCtx — 稳定 cache 前缀

需求：Claude 启用 prompt cache 时，希望 system + cold_zone 前缀跨轮稳定（便于 cache 命中）。需要确保 build_messages 永远先出 system，再出 cold_summaries 作为连续 System 消息，再出 hot messages。

pub struct ClaudeCtx {
    ctx_window: usize,
    max_output_tokens: Option<usize>,
}

impl ClaudeCtx {
    pub fn new(p: &ProviderConfig) -> Self {
        Self {
            ctx_window: p.context_window.max(128_000),
            max_output_tokens: p.max_tokens,
        }
    }
}

impl CtxBuilder for ClaudeCtx {
    fn build_messages(
        &self,
        conv: &Conversation,
        system_prompt: &str,
    ) -> (Vec<Message>, ContextStats) {
        // Claude 下 ctx_window 够大，直接用 legacy 窗口裁切
        let (mut messages, stats) =
            conv.to_provider_messages_budgeted(system_prompt, self.ctx_window);

        // 将来 provider 层想读 cache 位置时可以这样:
        // 1. 找 messages 里最后一条 System(system + cold_zone 块末尾)
        // 2. 这个位置就是 cache_control: ephemeral 该插的地方
        // 3. Claude provider payload assembler 自己去定位即可,不需要 ctx 返

        (messages, stats)
    }

    fn needs_compression(&self, conv: &Conversation, sys_tokens: usize) -> bool {
        conv.needs_compression(sys_tokens, self.ctx_window)
    }
    fn compression_plan(&self, conv: &Conversation) -> Option<(String, usize)> {
        let (c, n) = conv.build_compression_content();
        if c.is_empty() || n == 0 { None } else { Some((c, n)) }
    }
    fn truncate_tool_output(&self, r: &mut ToolResult, name: &str) {
        super::truncate::truncate_output(r, name, self.ctx_window);
    }
    fn name(&self) -> &'static str { "claude" }
}

注册：

    return Box::new(claude::ClaudeCtx::new(provider));
}

4.3 例：CustomFineTunedCtx — 完全替换 system prompt

需求：用户有个微调模型，训练时 system prompt 用的是自定义模板（比如 <|im_start|>system\n...<|im_end|>）。atomcode 默认的 system prompt 不能直接用，得替换。

pub struct CustomFineTunedCtx {
    ctx_window: usize,
}

impl CtxBuilder for CustomFineTunedCtx {
    fn build_messages(
        &self,
        conv: &Conversation,
        _base_system: &str,   // ← 忽略传入的 base
    ) -> (Vec<Message>, ContextStats) {
        // 完全替换成训练时匹配的模板
        const MY_TEMPLATE: &str = "<|im_start|>system\n\
            You are a helpful coding assistant. Tools: read_file, edit_file, bash.\n\
            Respond with JSON tool calls.\
            <|im_end|>";
        conv.to_provider_messages_budgeted(MY_TEMPLATE, self.ctx_window)
    }

    // ... 其他方法用默认 / 透传到 Conversation ...
    fn truncate_tool_output(&self, r: &mut ToolResult, name: &str) {
        super::truncate::truncate_output(r, name, self.ctx_window);
    }
    fn name(&self) -> &'static str { "custom-finetuned" }
}

注册：

if provider.model == "my-finetune-v1" {
    return Box::new(custom_ft::CustomFineTunedCtx::new(provider));
}

4.4 约定总结

要定制的维度 在 impl 里改 例
system prompt 文本变换 build_messages 开头变换 system_prompt 参数 OllamaCtx 砍工具 schema
system prompt 完全替换 build_messages 忽略参数、用自己模板 CustomFineTunedCtx 训练格式
触发压缩的阈值 重写 needs_compression OllamaCtx 40% 阈值
压缩后保留多少 / 怎么摘要 重写 compression_plan 自定义保留策略
工具输出裁切强度 重写 truncate_tool_output OllamaCtx 4K 上限
消息层直接定制（加入额外 marker、调顺序） build_messages 拿到 legacy 输出后再处理 ClaudeCtx 未来加 cache breakpoint 元数据
工具集按模型筛选 目前不在 ctx 范围（在 ToolRegistry 层） —
一致性保证：未命中任何规则的 provider 走 DefaultCtx，后者完全委托给 ctx::render——与重构前行为一致(render 模块的代码就是 2026-04 从 Conversation impl 平移出来的,byte-equivalent)。ctx/render.rs 里搬过来的 12 个 budgeted/sanitize 回归测试直接守护这层行为。
