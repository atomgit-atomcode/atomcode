# 会话历史按需展示

TUI 和 WebUI 恢复会话时，先展示近期历史，向上滚动时再读取更早的记录。
这只改变界面的历史传输和展示，不改变模型上下文、运行时恢复、压缩策略或会话文件。

## TUI

默认先读取最近 8 个已结束的完整回合，然后从本次读取的日志水位之后订阅新增事件。
若当前回合还在运行，整个当前回合由实时订阅补齐，包括未落盘的流式片段。
读取期间产生的新消息由订阅补齐。向上滚动接近已加载历史的顶部时，继续补载旧回合。
团队成员视图仍使用完整订阅；根会话的历史请求返回时不会插入当前正在查看的成员视图。

统计、TODO、压缩次数和 skill 使用记录通过不含旧正文的状态投影恢复，
不会因为只展示近期回合而归零。旧页使用独立渲染器，不重放到当前 TODO、输入框和实时回复状态。
撤销或压缩后，丢弃先前版本的在途页；已观察到新的日志事实后，后续请求使用更新的游标。

`[ui]` 的 `history_replay_max_rows` 仍是首次布局的行预算，不是分页的回合数。
设置 `history_replay_max_rows = 0` 或 `truncate_resumed_history = false` 会使用完整历史订阅和布局。
不支持分页读取的宿主保留完整订阅行为。

## WebUI

聊天、只读会话浏览和实时连接的初始快照默认只发送近期历史。
向上滚动或点击“加载更早的记录”可补载。现有浏览器消息缓存和 DOM 展示窗口继续工作。
补载不会覆盖最新 TODO，也不会重放旧消息为实时事件。
重连时，若游标证明历史前缀未改变且原始用户事件身份可定位，则保留已补载旧页；
否则重新建立近期显示窗口，避免沿用旧页索引导致空白。

详情接口通过 `recent=true` 选择分页，通过 `before=<JSON cursor>` 读取上一页。
不带参数的详情接口继续返回完整内容，供导出等调用方使用。
实时连接通过 `recent=true` 选择近期快照，内部运行时快照仍完整保留。
游标绑定项目、会话和未展示历史的内容摘要；追加新消息不会使它失效。
若撤销、压缩等改变了该前缀，接口返回冲突，界面提示刷新会话，避免拼接不同版本的历史。
已压缩出当前上下文的原始记录仍由已有的归档历史入口提供。

## 范围与限制

每页目标为 8 个回合、约 2 MiB；保持单个回合的工具调用与结果完整，
因此一个超大回合可以超过字节目标。WebUI 以真实用户输入划分显示回合，忽略合成的用户消息。

这一步减少初始正文传输、界面保留的正文和渲染工作，**没有**实现磁盘随机读取或运行时增量恢复。
服务端仍读取并投影完整日志；TUI 的统计/撤销等状态种子仍随历史元数据增长。
长会话的底层读取和模型恢复成本需要另行优化，不能用这次显示分页的结果推断已经消除。

## 验证记录

- 合入最新 `release/v5.2.7` 后，kernel、host-api、TUI、daemon 共 2,747 项测试通过。
- WebUI 415 项单元测试通过，包含重连时已加载历史的保留和失效判定。
- 审查补充修复了 TUI 状态种子清空摘要正文后丢失压缩计数的问题，并加入回归测试。
- `npm --prefix webui run test:history-pagination` 覆盖近期快照、按需补页、去重、补页期间实时回复、迟到旧页取消及只读会话补载。
- 现有 `session-browse-e2e.mjs`、WebUI typecheck/build、`bash gates/compile.sh` 和格式检查通过。
- 1,000 个 16 KiB 用户输入的合成日志：原始正文 16,384,000 字节，初始显示页加状态种子 301,968 字节。该数字不是磁盘读取或真实模型恢复耗时的测量。

构建验证使用独立的 `/tmp/atomcode-display-history-check-target`，避免与主工作区并行开发的编译产物混用。
